# 전략 운영팀 회의

## 팀
| 역할 | 누가 | 하는 일 |
|---|---|---|
| 자동 분석 | `strategy_council` 워커 (매일 KST 09:40) | 성적표 A~F 계산 → Redis `council:latest` + 텔레그램 요약 |
| 분석관 | `strategy-analyst` 에이전트 | 성적표·가상·그림자·실거래로 결론 초안 |
| 반박 감사관 | `strategy-auditor` 에이전트 | 결론을 렌즈 8개로 깨려고 시도 |
| 리드 | Claude Code | 둘을 합쳐 판정 · 기록 · 보고. 매매 판정 코드 변경은 리드만 |
| 결정 | **사장님** | 모드 켜기·끄기, 자본 — 에이전트는 바꾸지 않는다 |

## 절차
1. 리드가 운영 DB 읽기 / Redis `council:latest` 를 가져와 스크래치패드에 저장 (서버 주소는 프롬프트에만, 파일·보고서엔 쓰지 않음).
2. **한 메시지에 두 에이전트를 동시에** 띄운다 (`run_in_background`):
   - `strategy-analyst`: 「성적표 + 지난 회의 이후 바뀐 것 → 쓸 칸 / 멈출 후보 / 서로 돕는 조합 / 새 전략 상태」
   - `strategy-auditor`: 「같은 자료로 분석관이 낼 만한 결론(지난 회의 결론 + 성적표 E·F)을 렌즈 8개로 반박」
3. 리드 판정: 감사관이 기각한 결론은 채택하지 않는다. 조건부는 조건을 측정해서 닫는다.
4. 승격·강등 권고는 `new-strategy` 스킬 4절 기준으로. **권고까지만** — 바꾸는 명령은 사장님께 보고한다.
5. 기록: Obsidian `판정·측정/전략 운영팀 YYYY-MM-DD.md` + 개발일지 한 줄 + 대시보드 「결정 대기」.

## 보고 형식 (한국어)
- 한 줄 요약
- 표: 쓸 칸(장세별) · 멈출 후보 · 돕는 조합 · 새 전략 상태
- 권고(승격/강등/유지) + 사장님 결정이 필요한 것
- 「실패 없는 자동매매」는 없다 — 손실 상한(가족 차단기·전면 중단·하루 최대)이 함께 돈다는 것을 매번 확인한다.
