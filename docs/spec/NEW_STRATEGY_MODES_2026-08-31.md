# 「새 전략」 두 가지 방식 — 무엇이 다른가

> 사장님: "새전략 기본방식과 새전략 OBV자동의 차이를 정리해줘.
>  나도 이들 전략이 어떻게 진행되는지 알수없어"
>
> 코드에서 직접 확인해 정리한 것. 추측 없음.
> 판정 지점: `app/workers/stage_trigger_worker.py` (15초마다 전 전략 검사)

---

## 한 줄 요약

```
기본방식   :  가격이 트리거가에 도달  +  지표 확인   →  진입
OBV 자동   :  가격을 아예 안 본다.    지표 확인만    →  진입
```

**둘의 차이는 「2단계 이후를 무엇으로 여는가」 하나뿐입니다.**
1단계·자본·TP·손절은 완전히 같습니다.

---

## 1. 어디서 고르나

| 방식 | 버튼 | 내부 값 |
|---|---|---|
| 기본방식 | `+ 새 전략` | `trigger_mode = PRICE_DOWN_PCT` (LONG) / `PRICE_UP_PCT` (SHORT) |
| OBV 자동 | **`📊 새 전략 (OBV 자동)`** (보라색) | `trigger_mode = OBV_REVERSE` |

⚠️ OBV 자동은 **「직접 입력」이 강제**됩니다. 저장된 템플릿을 쓰면 그 템플릿의
`PRICE_DOWN_PCT` 가 따라와 **OBV 를 골랐는데 기본방식으로 도는** 사고가 있었습니다
(v130 silent bug). 지금은 템플릿 선택이 자동으로 비활성화됩니다.

---

## 2. 진행 순서

### 공통 — 1단계

```
사장님이 입력한 시작가에 LIMIT 주문 발송  →  체결되면 STAGE1_OPEN
```
두 방식이 완전히 같습니다.

### 기본방식 — 2단계 이후

```
① 가격 트리거 계산
     2단계 진입가 = 1단계 진입가 × (1 ± 트리거%)
     3단계 진입가 = 2단계 진입가 × (1 ± 트리거%)
     (SHORT 는 +, LONG 은 −)

② 현재가가 그 지점에 도달했는가?          ← 여기서 대부분 멈춤
        아니면 → 대기

③ Fix 55 / Fix 114 게이트
     · 24h 변동 필터 (참고용 — 지금은 차단하지 않음)
     · confirm_peak : 15분 반복 2회 + RSI/MACD/CCI 중 2개 꺾임

④ 통과 → 시장가 진입
```

### OBV 자동 — 2단계 이후

```
① 가격 트리거 = **사용하지 않음**  (트리거 % 칸을 채워도 무시됨)

② stage_entry_signal — 자동 진입 워커가 쓰는 **그 게이트 그대로**
     ⓐ obv_gate        4H OBV 가 세력 반대 방향 극단이면 차단
     ⓑ 양방향 차단     연속 실패 종목 차단
     ⓒ regime 차단     SHORT 에만 적용
     ⓓ confirm_peak    15분 반복 2회 + 지표 2개 꺾임

③ 통과 → 시장가 진입
```

## 3. 표로 비교

| | 기본방식 | OBV 자동 |
|---|---|---|
| 1단계 | 시작가 LIMIT | **같음** |
| 단계별 금액 | 입력 그대로 | **같음** |
| TP / 손절 / 트레일링 | 입력 그대로 | **같음** |
| **2~N단계를 여는 것** | **가격 도달** + 지표 | **지표만** |
| 트리거 % 칸 | 사용 | **무시됨** |
| 게이트 수 | 2개 (24h 참고 + confirm_peak) | **4개** |
| 시작가를 잘못 넣으면 | **치명적** — 트리거가 엉뚱한 곳에 깔려 영원히 미진입 | **영향 없음** (가격을 안 봄) |
| 언제 들어가나 | 내가 정한 **가격**에서 | 시스템이 판단한 **시점**에 |

## 4. 실제 사고로 본 차이 — `#1873 SKRUSDT SHORT` (2026-08-30)

시작가를 **0.11476** 로 입력했는데 SKR 의 실제 가격은 **0.016** 이었습니다 (약 7배).

**기본방식이었기 때문에** 이렇게 됐습니다:

```
1단계 트리거  0.11476    → LIMIT 미체결 (마진 500 만 점유)
2단계 트리거  0.149188   → 현재가의 6.5배 = 도달 불가
3단계 트리거  0.193944   → 도달 불가
```

포지션은 전부 「💉 포지션 추가」로 수동 진입됐고, 단계 계획은 세 개 다
`is_triggered=False` 인 채 남았습니다.

**OBV 자동이었다면** 가격 트리거를 안 보므로 **시작가 오입력이 2·3단계를 막지 않았습니다.**
(단, ⓓ confirm_peak 는 여전히 요구되므로 「급등 중 SHORT 추가」는 어렵습니다 — 5장 참조)

## 5. 둘 다 공유하는 한계 — `confirm_peak`

두 방식 모두 마지막에 **`confirm_peak`** 를 통과해야 합니다.

```
SHORT : 15분 반복 상승 2회 이상  +  RSI/MACD/CCI 중 2개가 「고점에서 꺾임」
LONG  : 15분 반복 하락 2회 이상  +  2개가 「저점에서 반등」
```

이것은 **「방향이 꺾인 뒤에 들어가라」**는 뜻입니다.
그런데 **물타기(손실 구간에서 추가 진입)** 는 **「아직 밀리는 중에 나눠 담는다」**입니다.
**두 요구는 정면으로 충돌합니다.**

실측:
- 볼밴 분할 17건에서 **3차 체결 0건** — 사유가 전부 `Fix114 정점 미확인` 이었다
- 그래서 볼밴만 예외 처리했다 (Fix 203 → 218 → 223)
- **일반 전략(기본방식·OBV자동)은 여전히 이 게이트를 그대로 받는다**

> **손실 구간에서 다음 단계가 자동으로 안 들어가는 근본 원인이 이것입니다.**
> 방식을 바꿔도 해결되지 않습니다.

## 6. 또 하나의 함정 — 손절이 단계에 잠긴다

`force SL`(ROI 기준 강제 청산)에는 **v130 게이트**가 있습니다:

```
다음 단계가 남아 있으면  →  손절 발동 안 함
```

의도는 「물타기 기회를 남긴다」인데, **단계 트리거가 도달 불가능하면** 이렇게 됩니다:

```
손절  →  단계가 남아서 잠김
단계  →  트리거 도달 불가로 영원히 안 열림
     ⇒  손절이 영원히 안 걸린다 = 청산될 때까지 보유
```

`#1873` 실측: `force_sl_roi_override = 5.00` 인데 현재 **ROI −58.5%**.
**손절선의 11배를 넘겼는데도 청산되지 않았습니다.**
`#1488` 이 −6,981 까지 갔던 구조와 같습니다.

## 7. 언제 무엇을 쓰나 (권고)

| 상황 | 권장 |
|---|---|
| **내가 정한 가격**에 정확히 담고 싶다 | 기본방식 |
| 가격보다 **시점**이 중요하다 / 시작가를 정확히 모르겠다 | **OBV 자동** |
| 급등·급락 종목 | **OBV 자동** — 가격 예측이 무의미한 구간이라 |
| 손실 구간 물타기 | **둘 다 부적합** (5장). 지금은 「💉 포지션 추가」로 수동 관리 |

⚠️ 어느 쪽이든 **시작가는 반드시 현재가 근처**여야 합니다.
기본방식에서는 시작가가 트리거 전체의 기준이 되고,
OBV 자동에서도 1단계 LIMIT 가격이 되기 때문입니다.
모달의 **「이 심볼 지금 분석」** 버튼으로 채우면 안전합니다.

## 8. 미해결 (다음 작업)

1. **일반 전략의 2·3단계에도 볼밴과 같은 예외**를 줄 것인가 —
   손실 구간 물타기에 「정점 확인」을 요구하는 것이 맞는지. 사장님 결정 필요.

   「트리거가 현재가에서 N배 이상 떨어져 있으면 단계 없는 것으로 본다」 같은 안전판 필요.
3. 시작가가 현재가와 크게 다르면 **모달에서 경고**할 것.
