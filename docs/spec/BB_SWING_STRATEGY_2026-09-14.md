# 볼밴 스윙 자동매매 (2026-09-14)

## 사장님 원문 (verbatim)
> 볼밴로직은 상승중인 차트와 보조지표일때 볼밴상단위로 올라가고 보조지표가 고점신호인때 숏을 분할진입하고 모든집입이 실패해서 모두 진입해고도 -10% 손실이면 청산하고 이익이 발행하면 빠른 tp1 부터 분할 익절하는 시스템으로 전략인트턴스를 구성하면 될것 같아
>
> 상승중 볼밴하단을 지지하면 다시 롱으로 같은 방식으로 전환하는 스윙자동매매를 하고 싶어 전략을 만들어줘

**현재 상태: 코드 작성 완료 · 기본 `shadow` (주문 없음).** 실주문은 사장님이 `bb_swing_mode=on` 으로 켠다.
⚠️ 아래 백테스트에서 **SHORT 쪽은 모든 변형이 적자**였다 → SHORT 는 켜지 말고 그림자 1주 데이터를 먼저 볼 것을 권한다.

## 1. 규칙 (코드: `app/services/bb_swing_rules.py`, 워커: `app/workers/bb_swing_worker.py`)

| 단계 | 내용 | 설정 키 (기본) |
|---|---|---|
| 상승중 | 완성된 4H 종가 EMA20 > EMA50 | `bb_swing_trend` (ema) |
| SHORT 진입 | 15m 종가가 상단 밖 **2봉 이상 연속** + 그 구간 최고 종가에서 **꺾임** + **RSI 고점 신호** (직전 3봉 최고 ≥ 70, 지금 하락) | `bb_swing_short_persist` (2) · `bb_swing_short_indicator` (rsi) · `bb_swing_rsi_high` (70) |
| LONG 진입 | 15m 저가가 **하단에 닿고 종가는 하단 위** = 하단 지지 | `bb_swing_support_tol_pct` (0) · `bb_swing_long_indicator` (none) · `bb_swing_rsi_low` (35) |
| 분할 | 1차 100 시장가 → 2차 200 · 3차 300 (1차 체결가 기준 약 2%씩 불리한 방향) | `bb_swing_capitals` (100,200,300) · `bb_swing_steps` (3,5,7) |
| 손절 | 평단 ROI **−10%** 전량. 계산상 **3차까지 다 들어간 뒤에만** 닿는다 (매 사이클 `check_no_dead_stage` 검산) | `bb_swing_sl_roi` (10) |
| 익절 | TP1 ROI **+5%** 부터 +10/+15/+20 에 **25%씩**, TP1 뒤 트레일링 3% | `bb_swing_tp1_pct` (5) · `bb_swing_trailing_pct` (3) |
| 전환 | 반대 신호가 오면 같은 가족 반대 포지션 잔량을 시장가 청산하고 새 방향 진입 | `bb_swing_flip_close` (1) |
| 한도 | 전용 동시 보유 2 · 심볼·방향당 24h 2회 · 감시 = 거래대금 상위 40 | `bb_swing_max_concurrent` (2) · `bb_swing_cycles_per_day` (2) · `bb_swing_top_n` (40) |
| 모드 | off / **shadow** / on | `bb_swing_mode` (shadow) |

- 숫자 중 사장님이 말한 것: −10% 손절, 빠른 TP1 분할 익절, 숏·롱 전환. 나머지는 볼밴 분할 기존값을 따르거나 **Claude가 정함**(설정 키로 뺌).
- 「−10% 손실」은 기존 볼밴 분할과 같이 **평단 ROI** 로 해석했다 (레버리지 2 = 가격 약 −5%).

### 실행 경로 = 볼밴 분할과 같다 (새 주문 경로를 만들지 않음)
`capital_management_mode=split_entry` 로 만들어서 기존 안전장치가 그대로 붙는다:
손절(`risk_service`) · 2·3차 실체결가 재앵커(`stage_trigger_worker`, Fix 209) · 피라미딩 제외(Fix 213) · 단계 정리 제외 · 반전 워커 제외.
진입 전 가드는 `surge_ladder_entry._guards_ok` (킬스위치 · API ban · 잔액 · 같은 심볼·방향 활성 · 전용 슬롯).
`strategy_type=bb_swing` 은 재진입 워커 화이트리스트에 걸리지 않는다 = **손절 뒤 자동 재진입·마틴게일 없음** (Fix 298 교훈).

## 2. 백테스트 (2026-09-14, 로컬 PC, 바이낸스 공개 시세)

조건: 거래량 상위 60종목 × 15m 1500봉(≈15.6일) + 4H. 실행 = 위 분할·손절·TP·트레일링 근사, taker 0.05%/체결.
단위 = 건당 USDT (1차 100 / 2차 200 / 3차 300, 레버 2). 「앞/뒤」= 기간 절반, 「홀/짝」= 종목 절반. 스크립트: 세션 스크래치 `bbswing_bt.py`.

### SHORT — 모든 변형이 적자 (4갈래 전부)
| 변형 | 건수 | 승률 | 건당 | 앞 / 뒤 / 홀 / 짝 | 3차 체결 · 손절 |
|---|---|---|---|---|---|
| 추세 무관 · 상단 밖 2봉 · RSI | 246 | 78.0% | **−2.96** | −3.17 / −2.73 / −2.95 / −2.97 | 34% · 17% |
| **4H EMA 상승중 · 2봉 · RSI (기본값)** | 191 | 75.4% | **−4.99** | −3.96 / −6.11 / −5.27 / −4.66 | 37% · 19% |
| 4H EMA 상승중 · 4봉 · RSI | 87 | 74.7% | −5.40 | −4.91 / −5.82 / −6.48 / −4.35 | 40% · 21% |

- 승률은 75% 안팎으로 높지만, 3차까지 물려 −60 USDT 손절이 나는 건이 이긴 건 여러 개를 지운다.
- **상승 조건을 강하게 걸수록 더 나빠진다** (−5.52 → −7.18 → −9.67). 상승장 역추세 SHORT 의 구조적 약점이다.
  (앞서 일봉 분석에서 「일봉 상단 밖 15분 반전 SHORT 승률 65→48%」와 같은 방향.)
- RSI 고점 신호는 손실을 줄이지만(−7.18 → −4.99) 흑자로 바꾸지는 못한다.

- 종목축은 둘 다 흑자지만 **시간축 뒷절반이 본전~적자** → 아직 채택 기준(4갈래 흑자) 미달.
- 신호가 하루 약 40건(60종목)이라 동시 보유 2로는 일부만 잡는다.

### MACD 를 고점 신호로 쓸 수 없는 이유
상단 밖에 머물다 꺾인 15m 봉 271건(25종목)에서 MACD 히스토그램이 **그 봉에 하락한 경우 0건**, 직전 3봉 안 하락도 22건(8%).
가격이 밴드 밖에 있는 동안 MACD 는 아직 올라가는 중이다 → 「상단 위 + MACD 고점」을 동시에 요구하면 진입이 구조적으로 불가능.
그래서 설정 선택지에서 MACD 를 뺐다 (`rsi | none`).

## 3. 반박 검증 (2026-09-14, 렌즈 3 — 실행 경로 상속 · 자금 안전 · 신호 정확성)

**상속 확인됨:** 손절 게이트 면제 · Fix 209 재앵커 · 정점-주춤/Fix 203/218/223 · 피라미딩·단계 정리·반전 워커 제외가 전부
`capital_management_mode` 로 갈라져 bb_swing 에도 붙는다. shadow 모드에서 주문·DB 생성 경로 없음. 킬스위치 확인 실패 = fail-closed.

**고친 것**
| 발견 | 심각도 | 조치 |

| 감시 종목에 비영문 심볼 | 중간 | 제외 (백테스트와 같은 표본) |

**남은 위험 (on 으로 켜기 전에 그림자 데이터로 확인)**
- **SHORT 2·3차가 OBV 게이트에 막힐 수 있다.** 볼밴 분할 2·3차는 Fix 218 「조정 신호」를 통과해야 하고, 그 안의 OBV 게이트는
  4H OBV 상승 비율 ≥ 0.35 면 SHORT 를 막는다. 스윙 SHORT 는 **상승 추세에서만** 진입하므로 막힐 가능성이 높다(분포 미측정)
  → 1차 100 만 들고 손절되는 쪽. 손실은 작아지지만 「3차까지 들어간 뒤 −10%」와 다르다. 공용 경로라 여기서 바꾸지 않았다.
- 금·은·원유·주식형 선물(XAU·XAG·CL·SOXL 등)이 거래대금 상위에 들어온다. 영문 심볼이라 제외되지 않는다.
- 24h 순위 게이트(`entry_chg24`)가 켜져 있으면 거래대금 상위 종목의 1차 주문이 자주 거절될 수 있다 (거절되면 보관 + 6시간 대기).

## 4. 켜는 법 · 되돌리는 법
1. 배포(사장님): `git pull origin main` → `docker compose restart api scheduler` (DB 마이그레이션 없음).
2. 배포 확인: `python scripts/verify_fix364_deploy.py` 의 「🌊 볼밴 스윙」 절 — 설정 실효값 · 마지막 스캔 · 그림자 신호 수.
3. **1주 그림자** 뒤 신호 수·결과 확인. 켤 때 권장: `bb_swing_sides=LONG` + `bb_swing_mode=on` (SHORT 제외).
4. 끄기: `bb_swing_mode=off` (재시작 불필요, 다음 분부터 적용). 이미 열린 포지션은 기존 손절·익절 경로가 계속 관리한다.
