**읽는 법 (반박 감사 반영 뒤)**
1. 출처 그대로는 **본전(±0.03R)**. 같은 날 무작위와의 차이는 **구별 불가** — LONG 차이 0.076R 은 표준오차(≈0.10R) 안, SHORT 우위는 신호 날이 40일뿐이고 최고 5일을 빼면 −0.36R.
2. 2차 손절(기준선 재이탈 종가 청산)은 LONG 에서 2R 고정보다 ≈−0.06R — 방향은 손해 쪽이지만 표준오차 안(청산 150건 중 74건이 기준선 청산).
3. 좋아 보이는 변형(EMA LONG +0.18, 거래량 끔 SHORT +0.25)은 같은 날 무작위도 같이 좋다(+0.22 / +0.18). 14개 줄에서 고른 최고값 = 다중 비교 함정. 가장 센 후보(거래량·OBV 끔 SHORT)도 날 묶음 95% 구간 [−0.08, +0.52] · 최고 5일 제외 −0.05R.
4. 모든 변형이 **2025 년 손실** — 한 장세 의존.
5. 🚨 **1차 손절이 너무 넓다** — 돌파 장대봉 때문에 손절폭 평균 10~12%, 15% 상한에 걸리는 비율 LONG 21% · SHORT 39% → 출처의 「직전 봉 저점 손절」이 실제로는 지켜지지 않는 건이 많다. 레버 2 기준 ROI −20~−30%.
6. 결론: **실주문 근거 없음. 그림자 + 가상매매로 운영 데이터 판정.** (스킬 절차: 결과가 나빠도 그림자로는 넣는다)

손절폭을 맞춘 무작위 대비 날 단위(날 묶음 부트스트랩 95%):
- 4h SHORT +0.089R [−0.078, +0.249] · 앞 +0.055 뒤 +0.122 · 최고 5일 빼면 +0.001 ← **가장 나음, 그러나 0 포함**
- 4h LONG +0.019 [−0.11, +0.15] · 1h L/S −0.012 / −0.046 · 1d L/S −0.064 / −0.126

**결론** — 승률 자체는 봉과 거의 무관(25~38%, 손익비 1:2 라 본전 승률 33%). 갈리는 것은 **비용**:
5m·15m 은 손절폭 1% 안팎이라 왕복 비용이 0.13~0.25R 를 깎아 무조건 손해. 1d·1w 는 신호가 너무 드물고 손절이 15% 상한에 걸림.
**4h 가 가장 적합**(SHORT 승률 38% · 비용 뒤 +0.17R · 앞뒤 절반 +), 1h 가 다음. 다만 4h 도 통계적으로 확정은 아님 → 그림자로 4h·1d 둘 다 기록.
→ 설정 `ichikijun_interval` 허용값 `("4h", "1d", "1h")`, **기본 4h**(Claude가 정함 — 출처는 일봉), 가상 규칙은 일봉 2개 + 4h 2개(15분봉 16개 묶음). 판정 기준(3절)은 4h SHORT 를 1순위로 사전 등록.

## 10. 실주문 「기준선 재이탈 청산」 (B-2, 2026-10-18 사장님 「다음으로 진행해줘」) — Fix 467

왜: 실험실 `r2kj` 변형(2R + 출처 2차 손절 = 종가가 기준선 재이탈하면 청산)은 가상에만 청산이 있고, 실주문은 손절·TP1 뿐 → 가상과 실주문 결과가 다르게 나온다(9-2 ⚠️). 과거 재생 1위 `4h_loose_pb_r2kj` 가 이 변형이다.

- 대상 = 포지션이 있는(ACTIVE_LIKE · 수량 ≠ 0) 인스턴스 중 `entry_signal LIKE 'ichikijun%'` 이고 `entry_signal_meta.variant` 가 기준선 청산 변형(`_r2kj`)인 것만. 다른 전략·가족은 손대지 않는다(CLAUDE.md 규칙 5).
- 판정 = 실험실 `simulate` 와 같은 정의: 진입 봉 **뒤** 완성봉 종가가 기준선(26) 반대편(LONG: 종가 < 기준선 · SHORT: 종가 > 기준선). 그 변형 봉(1h·4h·1d)의 새 완성봉이 생겼을 때만 klines 1회(Redis `ichiexit:last:{sid}:{iv}` — 같은 봉 재조회 없음). 아직 판정 안 한 봉 중 하나라도 이탈이면 이탈(장애로 놓친 봉 포함).
- 모드 `ichikijun_kijun_exit_mode`: `off` · **`shadow`(기본 — Claude가 정함, 실주문 청산이라 사장님이 켠다)** = 청산하지 않고 meta 에 `kj_exit_signal`(봉·종가·기준선) 1회 기록 + 로그 · `on` = 기존 `ExecutionService.emergency_close_position(전량)` 시장가 청산 + meta `kj_exit_done`.
- 15분마다(분 4·19·34·49). 실패 = 롤백·다음 사이클 재시도. 청산 중복은 emergency_close 의 5초 락 + 같은 봉 표식.
- 결과 검토(9-3) 표식: `기준선 청산 신호(그림자)` · `기준선 청산 실행` · (on 전에 끝난 건) `기준선 청산 없음`.
