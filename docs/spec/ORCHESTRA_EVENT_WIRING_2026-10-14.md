# 오케스트라 팀 「메시지에 반응」 설계 초안 (2026-10-14)

> 사장님 10/14 「1번 진행해줘」 — 팀 사이 메시지를 **누가 받아 무엇을 할지** 정하기 위한 초안. **코드는 아직 안 바꿨다.**
> 배경: [[Fix 449]] 때 운영 로그를 보니 팀 사이 메시지가 **받는 팀 없이 버려지고 있었다**(아래 표). 사장님 8/21 「오케스트라 지휘자가 각각의 에이전트팀을 컨트롤」의 남은 절반.
> 각 줄의 **결정** 칸을 사장님이 고르면 그대로 개발한다(✅ = Claude 추천).

## 0. 원칙 (모든 반응 공통)
1. **받는 쪽은 주문을 내거나 설정을 바꾸지 않는다** — 기록 · 알림 · 화면 갱신 · 자기 팀 일정 당기기만 (CLAUDE.md 규칙 2).
2. 알림은 **이미 있는 알림과 겹치지 않게** — 성적표(KST 09:40) · 아침 브리핑(KST 07:30) · 감시 워커 자체 알림이 이미 있다.
3. 받는 쪽이 실패해도 보내는 쪽은 그대로 돈다(버스가 실패를 세고 넘긴다 — Fix 449).
4. 정지·중단처럼 **여러 프로세스(api·scheduler)에 걸치는 것은 메시지가 아니라 DB 설정으로** 판단한다 — 버스는 프로세스 하나 안에서만 공유된다(Fix 449 반박 리뷰).
