## 4. 지금 바로 할 수 있는 것 / 결정이 필요한 것

**설정만으로 (재시작 불필요)**
- `pyramid_sides=LONG,SHORT` — LONG 에도 300 추가 (A3).
- `pyramid_min_move_pct=2.5` — 추가 트리거를 실제 ROI 5 에 맞춤 (A2).
- `pyramid_cap_loss_enabled=0` — 추가할 때 손절 ROI 자동 하향 중지 (A4). 단, 이러면 추가한 만큼 손절 금액이 커진다(옵션 −25% 가 610 증거금에 그대로 적용 = −152 USDT).

**코드 수정이 필요한 것 (사장님 결정 후 제가 진행)**
1. OBV 2·3단계를 **신호 시점 시장가**로 (B2/B5, 한 줄). 지금은 「좋은 자리」에 신호가 떠도 시작가 ±10%/32% 지정가에 걸린다.
2. OBV 2단계는 **손실 중에만**, 정리 함수는 **이익이면 정리 안 함** (A5/B1). 죽은 키 `auto_obv_stage2_trigger` 를 그 조건으로 살림.
3. 부분손절 때 손절선·total_capital **복원** (B4).
4. 잔량 10 USDT 방치 방지: `TP1_DONE_PARTIAL` 도 단계 후보에 포함 + 잔량 대기 상한 (B7).
5. 화면 「전략 ROI」 분모를 투입 자본으로(계획 910 으로 나눠 91배 과소 표시).

## 7. 반박 검증 4렌즈가 잡은 것 → Fix 363b 로 닫음
1. **단계 연쇄**: 2단계 시장가 발주 뒤 평단이 갱신되기 전(15초 사이클) ROI 가 여전히 ≤ −5 라 3단계까지 연쇄로 나갈 수 있었다 → 직전 단계 **체결 확인**(`is_triggered`) + 발주 **전** 15분 쿨다운(Redis, 실패 시 보류).
2. **가격/사다리/분할 전략까지 익절 뒤 상태를 보게 됨** → OBV 자동 인스턴스에만 한정.
3. **정리 생략이 「이긴 포지션에 600 얹기」로 변질**(정점-주춤 사다리는 이익 중에도 발동 가능) → 자동 단계는 이익 중이면 대기(모든 모드), 정리 함수는 자동이면 중단·수동(▶ 다음단계)만 생략.
4. **잔량 시계**가 인스턴스 첫 이벤트 기준이라 2단계를 거친 뒤 3단계 대기가 몇 분으로 줄 수 있었다 → 마지막 단계 체결 이후부터.
5. 옛 키 `auto_obv_stage{n}_trigger` 는 가격% 의미라 재사용하지 않고 전용 키 `obv_stage{n}_loss_roi_pct` 신설.
6. 이익 중 대기가 「차단」 배지로 보이던 것 → 배지 없이 정상 대기.
남긴 것(문서화): 잔량 상한은 강제손절 경로에만(강제손절 OFF 인스턴스는 대상 밖) · 정리 OFF 일 때 TP 부분청산과 단계 주문의 잠금 공유 없음(기존) · 화면의 OBV 2·3단계 「진입가」 표기는 주문에 안 쓰임.
