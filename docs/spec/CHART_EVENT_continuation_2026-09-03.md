## 0. 한 문장 결론

**「이 추세는 지속된다」를 혼자 말해주는 지표는 없었다.** 15개 지표 전부 효과크기
|d| < 0.13 이다. 그리고 **현행 채택안(「4H·15m 둘 다 MACD hist 상승 중」)은
SHORT 에서 5개 검증 게이트를 전부 탈락**했다 — 프로덕션이 SHORT 에서 가장 크게
좋아진다고 본 바로 그 조건이다. 대신 **「hist 가 상승 중」이 아니라 「hist 증분이
커지는 중(가속)」**과 **「변동성이 자기 기준 최고가 아님」**이 살아남았다.

## 1. 측정 설계

### 1-1. 이벤트 = 「추가를 할지 판단하는 순간」

포지션 기록이 아니라 캔들만 있으므로, **이미 수익 중인 상태**를 캔들로 정의했다.

| 항목 | 값 |
|---|---|
| 전제 (수익 중) | 최근 **12봉(3시간)** 동안 내 방향으로 **≥ +1.5%** 이동 |
| 샘플링 | 15m 봉 **4개마다(1시간)** 1회 |
| 이벤트 수 | LONG **1,504** / SHORT **1,543** (심볼 92 / 93) |
| 데이터 | 100종목 중 완전 데이터 **93종목**, 15m 499봉 · 4h 499봉 |

가격 1.5% 는 레버리지 2~3배에서 ROI 3~5% 에 해당한다. 즉 **현행 피라미딩
트리거(ROI +5%)가 걸리는 자리와 같은 구간**이다.

### 1-2. 라벨 = 추가분을 독립 미니 트레이드로

추가분(300 USDT)은 **그 시점 가격에 새로 들어가는 별개의 거래**다. 그래서
그렇게 라벨링했다.

- 진입: `close[i]`
- 목표: **+2.0 × ATR14**, 손절: **−1.2 × ATR14**
- 지평선: **32봉(8시간)**, 미도달이면 32봉 종가 정산
- 같은 봉에서 목표·손절이 둘 다 닿으면 **손절 우선** (보수적)
- `R` = 손절폭(1.2 ATR) 대비 배수

**기준선(base)**: LONG 승률 40.0% / R **+0.059**, SHORT 승률 41.6% / R **+0.074**.
즉 조건 없이 아무 데서나 추가하면 거의 본전이다.

### 1-3. 🚨 ATR 배리어를 쓴 이유 — 처음엔 고정 %였고, 그게 함정이었다

처음에는 목표 +2.5% / 손절 −1.5% 고정으로 쟀다. 그랬더니 SHORT 상위권을
`atr_rank_lo`(변동성 낮음)가 싹쓸이했다. **당연하다 — 변동성이 낮으면 고정 %
손절이 덜 닿는다. 지속성과 무관한 배리어 기하학이었다.**

그래서 배리어를 ATR 배수로 바꿔 다시 쟀다. 그런데도 `atr_rank_lo` 가 살아남았다
(부트스트랩 0.98/0.98). **그래서 이건 진짜다** — 다만 고정 % 라벨 하나만 봤다면
가짜와 진짜를 구분할 수 없었다. 최종 채택 규칙은 **두 라벨 모두에서** base 를
넘긴 것만 남겼다.

## 2. 🚨 가장 먼저 보고할 것 — 내가 만든 미래참조를 내가 잡았다

첫 측정에서 4H 지표가 압도적으로 나왔다.

```
h4l_accel  (4H 진행 중 봉 hist 가속)   d = +0.467 (LONG) / +0.476 (SHORT)   <- 전 지표 최대
h4c_accel  (4H 완료봉 hist 가속)       d = -0.040 / -0.085                  <- 거의 0
```

같은 지표인데 「진행 중 봉」만 극적으로 좋았다. **버그였다.**

프로덕션 `check_hist_rising(use_completed=False)` 는 라이브에서 `get_klines` 가
주는 **미완성 봉**(종가 = 현재가)을 읽는다. 그건 정당하다. 그런데 **과거 캔들로
백테스트할 때 그 자리에 「완성된 4H 봉의 종가」를 넣으면 최대 4시간 뒤의 값을
읽는 것**이다.

고쳤다 — 완료봉까지의 EMA 상태에 **현재 15m 종가**를 한 번 먹여 partial hist 를
재구성했다. 그러자:

```
h4l_accel  d = +0.467  ->  +0.035 (LONG)
h4l_accel  d = +0.476  ->  +0.062 (SHORT)
```

**효과의 90% 이상이 미래참조였다.** 이 파일의 모든 숫자는 고친 뒤의 것이다.

> 🔁 **교훈**: 4H·1h 같은 상위 타임프레임을 15분 시점에 갖다 쓸 때, 그 봉이
> 「그 시점에 이미 닫혀 있었는가」를 반드시 확인할 것. 안 닫혔으면 **현재가로
> 재구성**해야 한다. 로그·코드는 정상으로 보였고 숫자만 너무 좋았다.
> (헌법: 「너무 좋은 결과는 미래참조를 의심하라」가 정확히 이 경우다.)

## 3. 검증 게이트 — 6개를 전부 통과한 것만 채택

| 게이트 | 내용 |
|---|---|
| ① 지평선 | 16봉 / 32봉 / 64봉 **전부** base 초과 |
| ② 홀/짝 | 심볼 index 홀·짝 두 그룹 **양쪽 다** 자기 base 대비 개선 |

**권고**: 현행 조건을 지금 끄자는 것이 아니라, **아래 대체안과 A/B 로 같이 재라.**
현행 조건을 유일한 관문으로 쓰는 것은 근거가 약하다.

### 5-1. 「상승 중」이 아니라 「가속」이다 — 이번 최대 발견

현행은 `hist[-1] > hist[-2]` (**1차 미분 = 상승 중**)를 본다. 이번에 이긴 것은
**2차 미분**이다:

```
가속 = (hist_현재 - hist[k]) * sgn  >  (hist[k] - hist[k-1]) * sgn
       ─────────────────────────      ─────────────────────────
       지금 봉의 증분                  직전 봉의 증분
```

즉 **「내 편으로 가고 있다」가 아니라 「내 편으로 가는 속도가 빨라지고 있다」**.
사장님 말씀의 「**지속** 상승이나 하락이 데이터를 보이면」에 더 가까운 것은
후자다 — 힘이 붙는 중인지를 본다.

| | SHORT R | LONG R |
|---|---|---|
| hist 상승 중 (현행) | +0.072 (base 미달) | +0.077 |
| **hist 가속 중** | **+0.124** | **+0.116** |

### 5-2. 🚨 `pos_in_4h_bar >= 0.25` 가 왜 붙었나 — 가속 조건의 함정

4H 진행 중 봉은 **봉이 얼마나 진행됐느냐**에 따라 증분 크기가 달라진다.
실제로 가속 조건의 발동률이 4H봉 진행에 따라 이렇게 움직인다:

| 4H봉 내 위치 | 0~25% | 25~50% | 50~75% | 75~100% |
|---|---|---|---|---|
| 가속 발동률 (LONG) | **13%** | 53% | 74% | **93%** |
| 가속=T 일 때 R (LONG) | **−0.323** | +0.087 | +0.212 | +0.124 |
| 가속=F 일 때 R (LONG) | +0.003 | +0.010 | −0.119 | −0.130 |

**4H봉 첫 1시간에는 부호가 뒤집힌다** (LONG −0.323). 봉이 막 시작해 증분이
아직 작을 때의 「가속」 판정은 신뢰할 수 없다. 그래서 채택 규칙에 전부
**`4H봉 25% 경과(= 1시간) 이후`** 를 붙였다.

> 🔁 이건 Fix 291 이 지적한 「15분은 완료봉을 쓰는데 게이트만 진행 중 봉을 본다」와
> 같은 뿌리의 문제다. **진행 중 봉을 읽는 판정은 「봉 안 어디쯤인가」를 함께 보라.**

## 6. 🚨 반증 — 이번에 깨진 가설들

### ① 「지속 지표가 많이 모일수록 좋다」 — 반증

15분 지속 지표 9개(hist상승/hist부호/RSI유지/밴드확장/OBV확인/EMA정렬/거래량유지/
실체/CCI부호)를 세서 점수로 만들었다. **단조성이 전혀 없다.**

```
LONG  s15=3 -0.026 | s15=4 +0.289 | s15=5 +0.068 | s15=6 -0.133 | s15=7 +0.092 | s15=8 +0.102 | s15=9 +0.093
SHORT s15=3 +0.185 | s15=4 +0.183 | s15=5 +0.076 | s15=6 +0.072 | s15=7 +0.083 | s15=8 -0.073 | s15=9 +0.271
```

SHORT 는 **8개 맞을 때가 최악(−0.073)**이다. 「N중M 합의」식 점수 모델은
이 국면에서는 쓰면 안 된다.

### ② 「4H 가 더 많이 동의할수록 좋다」 — 반증 (사장님 정정이 옳다)

4H 맥락 지표 4개(hist상승/hist부호/EMA정렬/OBV확인) 동의 개수별:

```
LONG   4H=1 +0.004 | 4H=2 +0.135 | 4H=3 +0.075 | 4H=4 -0.006   <- 4개 전부 동의가 최악
SHORT  4H=0 +0.200 | 4H=1 +0.035 | 4H=2 +0.111 | 4H=3 +0.113 | 4H=4 -0.048   <- 4H=0 이 최고
```

**4H 가 전부 내 편일 때가 오히려 가장 나쁘다.** SHORT 는 4H 가 하나도 동의하지
않을 때(n=73)가 +0.200 으로 최고였다. 4H 를 **통과 조건(거부권)** 으로 쓰면 안
된다는 사장님 정정이 **이 데이터에서 그대로 확인된다.** 4H 는 특정 조합
(가속 + EMA정렬 / 가속 + OBV) 에서만 가중치로 기여한다.

### ③ 「거래량이 유지돼야 지속된다」 — 반증 (SHORT 는 정반대)

```
SHORT  vol_hold (3봉 평균 / 20봉 평균 >= 1.0)  n=579  R(고정%) -0.105  vs base +0.035
       지속(승) 평균 거래량비 1.011  vs  반전(패) 1.112   d = -0.122
```

**SHORT 는 거래량이 많을수록 반전한다.** LONG 은 무관(d=+0.007).
「줄면 힘이 빠진 것」은 이 국면에서 틀렸다.

### ④ 「밴드가 벌어져야 추세다」 — 부분 반증

`bw_expand`(밴드폭이 3봉 전보다 큼)는 LONG·SHORT 모두 효과가 없었다
(d = +0.012 / +0.029). 살아남은 것은 **밴드폭의 자기 순위**(LONG)와
**ATR 자기 순위가 낮을 것**(SHORT)이다. **변화 방향이 아니라 수준**이다.
그리고 SHORT 는 **변동성이 자기 기준 최고가 아닐 때** 더 지속됐다 —
「확장 = 추세」의 반대다.

### ⑤ 「RSI 가 과매수에 머물면 강한 추세」 — 반증

```
LONG   rsi_stay70 (RSI>=70)  n=375  R(고정%) -0.056  vs base +0.029
SHORT  rsi_stay70 (RSI<=30)  n=304  R(고정%) -0.161  vs base +0.035   <- 전 조건 중 최악
```

**극단에 머무는 것은 지속이 아니라 반전 신호**였다. 그래서 채택안은
`rsi_stay70` 이 아니라 **`50 ≤ RSI방향값 < 80` 밴드**다.

### ⑥ 「OBV 가 가격과 같이 가야 확인이다」 — LONG 에서 반증

15m 10봉 신고가(`px_ext`) 안에서 갈라보면:

```
OBV 확인    n=479  승률 39.7%  R +0.059
OBV 미확인  n=149  승률 49.0%  R +0.284    <- 다이버전스 쪽이 낫다
```

기여가 몇 종목에 몰린 것도 아니다 — 69개 심볼, 상위 3심볼을 빼도 +0.181 이다.
**다만 이건 사장님 사상(「지속」)과 결이 다르다.** 통과율 10% 로 얇고, 표본
149건이다. **소액으로 별도 검증 후 채택**을 권한다. 최소한 **「OBV 가 확인해야
추가한다」는 조건은 걸지 말아야 한다** — 그게 더 나쁘다.

### ⑦ 「연속 양봉/음봉 수」 — 효과 없음

```
consec3 (3봉 연속)  LONG R +0.004 / SHORT R -0.025
지속(승) 평균 연속봉 1.533  vs  반전(패) 1.527   d = +0.004
```

### ⑧ 지속 vs 반전 기술통계 — 「단일 지표는 없다」

승(지속) / 패(반전) 두 집단의 지표 평균 차이:

| 지표 | LONG d | SHORT d |
|---|---|---|
| runup (이미 간 폭) | +0.020 | +0.081 |
| RSI14 방향값 | +0.036 | −0.053 |
| CCI9 방향값 | +0.019 | −0.037 |
| OBV 기울기(정규화) | −0.001 | +0.060 |
| 밴드폭 자기순위 | +0.115 | −0.044 |
| **ATR 자기순위** | +0.101 | **−0.125** |
| **거래량 3봉/20봉** | +0.007 | **−0.122** |
| 실체비율 | +0.066 | −0.081 |
| 연속봉 수 | +0.004 | +0.016 |

**전부 |d| < 0.13.** 참고로 이 저장소에서 「종목 선정 최대급」이라 부른 값이 2.08 이다.
**「지속」은 단일 지표로 안 잡힌다** — 조합에서만 겨우 d ≈ 0.14~0.34 가 나온다.
그래서 이 국면의 규칙은 전부 **효과가 작다**. 정직하게 그렇게 보고한다.

## 7. 1차 추가 vs 2차 추가 — 조건이 달라야 한다 (사장님 질문 ④)

runup < 4% 를 1차 추가 자리, ≥ 4% 를 2차 추가 자리로 나눴다.

| | 1차 base R | 2차 base R | 방향 |
|---|---|---|---|
| **LONG** | +0.040 | **+0.098** | **2차가 더 좋다** |
| **SHORT** | **+0.082** | +0.049 | **1차가 더 좋다** |

**LONG 과 SHORT 가 정반대다.**

| 규칙 | 1차 R (vs base) | 2차 R (vs base) | 판정 |
|---|---|---|---|
| S_H4_ACCEL_OBV4H | +0.214 (+0.132) | +0.215 (+0.166) | **양쪽 다 OK** |
| S_H4_ACCEL_RSI_BAND | +0.166 (+0.084) | +0.127 (+0.078) | 양쪽 OK |
| **S_ATR_LO_H4_CONSEC2** | +0.295 (+0.213) | +0.076 (**+0.027**) | **1차 전용** |
| S_ATR_RANK_LO | +0.154 (+0.072) | +0.076 (+0.027) | 1차 우선 |
| S_H4_ACCEL_EMA4H | +0.202 (+0.120) | +0.547 (+0.498, n=45) | 2차는 표본 부족 |
| L_BODY_H4_ACCEL | +0.177 (+0.137) | +0.259 (+0.161) | **양쪽 다 OK** |
| L_OBV_DIVERGE | +0.204 (+0.164) | +0.496 (+0.398, n=41) | 2차 표본 부족 |
| **현행 PROD (SHORT)** | +0.101 (+0.019) | **−0.032 (−0.081)** | **2차에서 손실** |

**권고**
- **SHORT**: 1차 추가를 주력으로. 2차는 `S_H4_ACCEL_OBV4H` 만. 현행 조건은
  2차에서 base 보다 −0.081 이므로 **2차에 쓰지 말 것.**
- **LONG**: 2차가 더 좋다. `L_BODY_H4_ACCEL` 을 1·2차 공통으로.

## 8. 결론 못 낸 것

1. **프로덕션 실측(n=88/45)과의 정면 충돌**을 이 데이터만으로는 못 가른다.
   실거래 손익 귀속(마틴게일·TP 사다리 포함)과 독립 미니 트레이드는 다른 것을
   잰다. **두 조건을 실계좌에서 병행 기록**해야 갈린다.
2. **`L_BW_OBV_DIVERGE`(승률 55.6%, d=+0.343)** 는 이번 최대 효과인데 n=108,
   통과율 7% 다. 6개 게이트를 전부 통과했지만 **얇다.** 그리고 사장님 사상의
   「지속」과 결이 다르다(다이버전스 = 힘이 빠지는 신호). 소액 검증 필요.
3. **15m 데이터가 5일뿐**이다. 시간 분할이 「같은 5일 안의 전·후반」이라
   진짜 out-of-sample 이 아니다. 심볼 부트스트랩으로 보완했지만 한계다.
4. **2차 추가의 SHORT 표본**(S_H4_ACCEL_EMA4H n=45, L_OBV_DIVERGE n=41)은
   30건은 넘지만 결론 내기엔 얇다.
5. **수수료·슬리피지 미반영.** R +0.1 은 손절폭의 10% 이므로 왕복 수수료
   0.08% 가 ATR 대비 얼마인지에 따라 상당 부분이 깎일 수 있다.

## 9. 코드에 넣을 때

`docs/spec/CHART_EVENT_continuation_2026-09-03.json` 의 `helpers` 를 그대로
구현하면 된다. 특히:

- `h4_hist_accel` 은 **진행 중 4H 봉의 partial hist** 를 쓴다. 라이브에서는
  `get_klines("4h")` 의 마지막 원소가 이미 그것이므로 추가 작업이 없지만,
  **백테스트·재현 시에는 완성 종가를 쓰면 안 된다.**
- `pos_in_4h_bar >= 0.25` 를 반드시 함께 건다.
- ATR·밴드폭은 **절대값 금지, 자기 순위(최근 100봉)** 로만.
- OBV 기울기는 **거래량 정규화** 필수.

⚠️ 이 규칙들은 전부 **효과크기 0.07~0.34** 다. 「추가를 켜면 좋아진다」가 아니라
「추가를 **아무 데서나 하는 것보다** 조금 낫다」는 크기다. 기본 OFF + 설정으로
빼고, 실계좌 기록으로 재검증할 것을 권한다.
