## 1. 결론 먼저

**사장님 사다리 구조는 실측이 지지합니다. 다만 1단계 진입 자리를 바꿔야 합니다.**

급등 사건(24h +30% 돌파) **76건**을 그 시점부터 4일간 걸으며 시뮬레이션했습니다:

```
1단계 조건        2단계          사건수   합계 USDT     건당
즉시             없음             75    -1,375.00   -18.33
즉시             8%↓+주춤         75    -1,686.42   -22.49   ← 2단계가 오히려 악화
8%↓             없음             75      -105.71    -1.41
8%↓             8%↓+주춤         39      +144.29    +3.70   ← 유일한 흑자
```

- **나쁜 자리 위에 사다리를 얹으면 더 나빠진다** (−18.33 → −22.49)
- **좋은 자리 위에서는 사다리가 값을 더한다** (−1.41 → +3.70)

뒷받침하는 별도 측정 — SHORT 90건을 「정점 대비 어디서 들어갔나」로 나누면:

```
정점 대비 하락      건수   승률       합계        건당
① 0~1% (정점)      11    0.0%   -1,470.68   -133.70   ← 승자 0명
② 1~3%             23   13.0%     -634.98    -27.61
③ 3~8%             33   21.2%   -1,169.68    -35.44
④ 8% 이상          23   43.5%      +605.76    +26.34   ← 유일한 흑자
```

**정점에서 바로 SHORT 한 11건은 전부 졌습니다.**

이건 사상 ① 원문과 오히려 일치합니다 — *"지표 최고점에서 하락·지지를 **여러번 반복한 뒤 하락 시작**"*.
「정점」이 아니라 **「하락이 시작되어 진행된 뒤」**입니다.

## 5. 설계

### 5.1 모니터링 대상

```
rank_map(get_24hr_ticker(), 10) 의 UP 1~10위
  AND quoteVolume >= 5,000,000      (market_movers.MIN_QUOTE_VOLUME)
  AND Symbol.status == "TRADING"     (신규 — 지금 어떤 워커도 안 본다)
```

⚠️ **「당일」 vs 「24h」** — 코드의 모든 랭킹은 **롤링 24시간**입니다. KST 캘린더 당일 기준은
저장소 전체에 없습니다. 사장님 「당일」이 롤링 24h 면 기존 것으로 충분하고,
진짜 당일이면 별도 스냅샷이 필요합니다. **확인 필요.**

### 5.2 진입 판정 (1·2·3시도 **동일**)

**필수 — 전부 AND. 「N중 M」 다수결 금지 (Fix 250 사고).**

| # | 조건 | 근거 |
|---|---|---|
| M1 | 급등 1~10위 + 거래대금·상장 필터 | 사장님 원문 |
| M2 | 최근 4H 6봉 중 1봉 이상 **종가 > BB(20,2) 상단** | 사상 ①·⑥ (4H = 국면) |
| M3 | **정점 대비 하락 ≥ 8%** | **실측: 8% 미만 전부 적자, 8%↑ 만 +26.34/건** |
| M4 | **신고점 갱신 정지 ≥ 5봉(75분)** | Fix 260 에서 독립 검증된 「주춤」 |
| M5 | OBV 극단 상승 아님 (`check_obv_gate`) | 사상 ④ |

🚨 **M3 이 이 설계의 핵심입니다.** 사장님 원문의 「최고점에 조정 시작」을
「정점 도달 즉시」로 구현하면 **승률 0%** 입니다.

**기록만 (진입 판정에 0점 기여)**: 4H MACD hist 방향, 4H CCI 부호.
효과크기 2.08 / 2.00 으로 최대급이지만 그건 **종목 선정** 축이었고,
반대매매 타이밍에 쓰자 −118~−145 USDT 로 해로웠습니다.

### 5.3 사다리 상태기계

```
WATCH → (M1~M5) → 1시도 500/-5%
                      ├─ 익절 → DONE (쿨다운)
                      └─ 손절 → WAIT → (M1~M5 재성립) → 2시도 1000/-10%
                                                          ├─ 익절 → DONE
                                                          └─ 손절 → WAIT → 3시도 500/-5%
                                                                              └─ 손절 → COOLDOWN
```

**승격 조건 (무조건 아님 — 사상 ⑦)**
- 직전 시도가 **손절로** 끝났을 것 (수동 청산·킬스위치는 승격 금지)
- 해당 심볼 사이클 누적 손실이 상한 미만
- 계정 당일 손실이 상한 미만
- preflight 통과 (**자본 × 1.05** — 자본 1000 이면 **1050 USDT** 필요)

**상태 저장 = 신규 DB 테이블 `surge_ladder_state` (alembic 0034)**

🚨 **Redis 금지.** `docker-compose.yml` 의 redis 에 volume 도 `--appendonly` 도 없습니다.
재기동 한 번이면 카운터가 0 이 되어 **이미 1,500 을 잃은 심볼에 다시 500 이 나갑니다.**
그건 사장님이 직접 인정하신 *"큰손실 후 무리한 투자로 손실 반복"* 을 시스템이 자동 재현하는 경로입니다.

### 5.4 하드 상한

| 범위 | 상한 | 계산 |
|---|---|---|
| 심볼당 사이클 | **−150** | 25 + 100 + 25 |
| 동시 종목 | **전용 키** `surge10_max_concurrent` | 전역 슬롯과 **별개**로 세야 한다(③ 참조) |
| 일일 | **전용 카운터** | 유니버스가 30초마다 회전하므로 「10종목 × 150」은 하루 상한이 **아니다** |

🚨 **유니버스 회전**: 하루에 수십 개 심볼이 top-10 을 통과합니다.
심볼별 쿨다운만으로는 계정 전체 손실이 묶이지 않습니다. **일일 손실 상한이 필수**입니다.

## 6. 알려진 미해결 — 구현 전에 풀어야 함

1. **`peak_stall` 은 `trigger_price` 필수 인자** (`peak_stall.py:196, 225-227`).
   독립 포지션엔 stage plan 두 행이 없어 `ok` 가 영원히 False.
   → 정점 가격을 trigger 로 넘기고 `gap_pct` 를 급등률에서 유도하는 대체 필요.
2. **`confirm_peak` 반환형은 `tuple[bool, str, dict]`** — `== True` 는 항상 False,
   `if confirm_peak(...)` 는 항상 참. 반환값을 언패킹해야 함.
3. **`confirm_peak` / `check_obv_gate` 는 예외·데이터 부족 시 fail-**open**** — 「필수」라고 부르려면
   호출부에서 fail-closed 로 감싸야 함.
4. `min_swings` 를 0 으로 낮추면 사상 ①의 **「여러번 반복」이 삭제**됩니다.
   이건 사상 변경이므로 사장님 승인이 필요합니다.
