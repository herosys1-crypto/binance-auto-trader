## 🎯 왜 「같이」가 핵심인가

두 전략은 **성격이 정반대**입니다.

| | 📐 EMA/VCP (v137) | ☁️ SAR/구름대 (v138) |
|---|---|---|
| 유형 | **돌파형** | **추세추종형** |
| 노리는 순간 | 변동성 수축 후 **터지는 첫 순간** | 이미 난 추세에 **올라타서 꺾일 때까지** |
| 강점 | 초기 진입가 우수, 손절폭 최소 | 큰 추세를 끝까지 먹음 |
| 약점 | 가짜 돌파(휩쏘) | 진입이 늦음, 횡보장에서 잦은 손실 |
| 청산 기준 | 20 EMA 종가 이탈 | SAR 전환 / 구름 이탈 |

**서로 다른 시점을 보기 때문에 합의가 의미가 있습니다.**
- 둘 다 OK → 서로 다른 근거 2개가 같은 방향 = 신뢰도 상승
- **한쪽이 금지** → 사장님이 못 봤을 **반대 근거**가 있다는 경고

> 이게 「같이 적용」의 실익입니다. 두 카드를 나란히 띄우는 게 아니라,
> **서로를 검증**시키는 겁니다.

## 🎛 기계화된 판정 규칙

`backend/app/services/sar_ichimoku_analyzer.py` — 임계값은 전부 클래스 상수 (헌법 6번 단일 진실).

### 1) 파라볼릭 SAR (Wilder 원식)

```
SAR(t+1) = SAR(t) + AF × (EP - SAR(t))
  AF  = 0.02 시작, 신고점/신저점 갱신마다 +0.02, 최대 0.2
  EP  = 추세 중 극값 (상승=최고가 / 하락=최저가)
  제약 = SAR는 직전 2봉의 저가(상승)/고가(하락)를 넘을 수 없음
  전환 = 저가가 SAR 하회(상승 중) or 고가가 SAR 상회(하락 중)
         → SAR = 직전 EP, EP 리셋, AF 리셋
```
| 상수 | 값 |
|------|-----|
| `SAR_STEP` / `SAR_MAX` | 0.02 / 0.2 (원본 기본값!) |
| `FLIP_FRESH_BARS` | 3 — 전환 후 3봉 이내 = 「첫 점」 |

> `flip_bars_ago = 0` → 직전 완료봉에서 전환. 3봉 초과 = **추격 진입**이므로 방아쇠로 안 칩니다.

### 2) 일목 구름대 (구름만!)

```
전환선   = (9봉  최고 + 최저) / 2
기준선   = (26봉 최고 + 최저) / 2
선행스팬1 = (전환선 + 기준선) / 2   → 26봉 앞으로 이동
선행스팬2 = (52봉 최고 + 최저) / 2  → 26봉 앞으로 이동
구름 상단/하단 = max/min(선행스팬1, 선행스팬2)
```
= 현재 봉의 구름은 **26봉 전 데이터**로 만들어진 것입니다 (코드에서 `src = i - 26`).

| 판정 | 조건 |
|------|------|
| `ABOVE` | 종가 > 구름 상단 → 상승 추세 |
| `BELOW` | 종가 < 구름 하단 → 하락 추세 |
| `INSIDE` | 구름 내부 → **추세 불명 = 관망!** |

| 상수 | 값 | 의미 |
|------|-----|------|
| `THIN_CLOUD_PCT` | 1.5% | 구름 두께 ≤ 1.5% = 얇음 (저항 약함) |
| `NEAR_CLOUD_PCT` | 2.0% | 구름까지 이격 ≤ 2% = 눌림목 근접 |

> 얇은 구름 **또는** 눌림목 근접 = 원본의 「가장 이상적」 조건 → `ideal` 플래그 + 10점.

### 3) 타임프레임별 역할

| 봉 | 판정 |
|----|------|
| **4H** | 구름 위치만 → 방향 허가 (`INSIDE` = 양방향 금지) |
| **1H** | 같은 방향 구름 유지 + `ideal` 가산 + SAR 방향 참고 |
| **15m** | 구름 방향 유지 + SAR 방향 일치 + **신선한 전환** = 방아쇠 |

### 4) 산출 레벨

| 항목 | 값 |
|------|-----|
| 손절 | 15m **구름 반대편 끝** (LONG=하단 / SHORT=상단) — 원본의 「구름 이탈 마감」 |
| 리스크% | \|현재가 − 손절가\| / 현재가 × 100 |
| 절반 익절 | 15m SAR 전환 (`sar_15m` 값 제공) |
| 전량 익절 | 1H SAR 전환 (`sar_1h` 값 제공) |

## ⚠️ 리페인팅 방지 (v137보다 더 중요!)

**SAR는 진행 중 봉에서 찍혔다 사라질 수 있습니다.** 진행 중 봉의 저가가 잠깐 SAR를 뚫으면
전환된 것처럼 보이다가, 봉이 마감될 때 되돌려지면 없던 일이 됩니다.

→ **SAR·구름 판정은 전부 완료봉만 사용합니다** (`klines[:-1]`).
현재가는 `current_price` 로 따로 보고합니다.

이건 헌법 v127(진행 중 봉 신뢰 금지)의 연장이며, 이걸 안 지키면
「신호 떴다가 사라지는」 전형적인 silent bug가 됩니다.

단위 테스트 `test_구름은_완료봉_기준_리페인팅_방지`가 이걸 강제합니다 —
진행 중 봉 종가를 1.0으로 폭락시켜도 판정이 안 바뀌어야 통과합니다.

## 🤝 합의(Confluence) 판정

`backend/app/services/strategy_confluence.py`

| 조합 | level | 판정 | 점수 |
|------|-------|------|------|
| A + A | `STRONG_AGREE` | 🔥 최상위 합의 | 평균 |
| A + B / B + B | `AGREE` | ⭐ 합의 | 평균 |
| C 포함 (D 없음) | `PARTIAL` | 👀 관망 권장 | 평균 |
| **한쪽만 D** | `CONFLICT` | ⚠️ **충돌 경고** | 평균 **× 0.5** |
| 둘 다 D | `AVOID` | 🚫 진입 금지 | 0 |
| 한쪽 판정 불가 | `NONE` | ➖ 합의 없음 | — |

**충돌 시 점수를 절반으로 깎습니다.** 한쪽이 금지라고 하는데 다른 쪽 근거만 보고
들어가는 걸 막기 위해서입니다.

### 심볼 분석 진입 판단 반영

| 항목 | 점수 |
|------|------|
| 각 전략 A / B / C / D | +15 / +8 / 0 / **−20** |
| 합의 `STRONG_AGREE` | +15 |
| 합의 `AGREE` | +8 |
| 합의 `CONFLICT` | **−15** |

최종 점수는 **0~100으로 고정**됩니다 (v138에서 지표가 늘어 100 초과가 가능해졌기 때문).

## 🎓 학습 시스템 연결

진입 시 `entry_context`에 **세 덩어리**가 함께 박제됩니다:

```json
{
  "ema_vcp":      { "grade": "A", "vcp_contracting": true, ... },
  "sar_ichimoku": { "grade": "B", "cloud_4h": "ABOVE", "sar_fresh_flip": false, ... },
  "confluence":   { "level": "AGREE", "agree": true, "conflict": false,
                    "grades": {"ema_vcp": "A", "sar_ichimoku": "B"} }
}
```

### 집계
```
GET /api/v1/trade-learning/setup-stats?days=90
```
| 필드 | 내용 |
|------|------|
| `grades` | 📐 EMA/VCP 등급별 승률 |
| `sar_grades` | ☁️ SAR/구름대 등급별 승률 |
| **`confluence`** | 🤝 **합의 수준별 승률** ← 「같이 적용」이 이득이었나? |
| `flags` | 개별 조건별 승률 (13종: VCP 수축 / 구름 위치 / SAR 신선도 …) |
| `verdicts` | 사장님용 한 줄 결론 **여러 개** (전략별 + 합의) |

**핵심 결론 문구**:
> 🤝 합의 평균 +X% vs 충돌 평균 +Y% = **두 전략 같이 보는 게 이득!** ✅

이게 나오면 「같이 적용」이 실제로 돈이 됐다는 증거입니다.
표본 **10건 미만이면 판정하지 않습니다** (`min_sample`).

### Binance 호출 절감
4h/1h/15m 캔들을 **1회만 조회해서 두 분석기가 공유**합니다.
- 심볼 분석 1회 = 캔들 2회 추가 (15m은 기존 것 재사용)
- 학습 저장 = 신규 record 1건당 3회 (진행 중 스냅샷엔 안 붙임)

5. 손절/익절 값은 **기준선**이며 실제 SL/TP(강제 SL, 트레일링, TP1 옵션)를 대체하지 않습니다.
