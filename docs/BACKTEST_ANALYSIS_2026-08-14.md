### 버그 ① 학습 저장 전면 실패 (v134 이후 계속)

`TradeLearningService`가 `StrategyInstance`에 **없는 속성 5개**를 참조하고 있었습니다.

| 참조한 속성 | 실제 존재? |
|---|---|
| `first_entry_at` | ❌ |
| `planned_capital` | ❌ |
| `unrealized_pnl_pct` | ❌ |
| `close_reason` | ❌ |
| `current_price` | ❌ |

**프로덕션 실측 증거**

```
학습 record 37건 → status='CLOSED' 0건 (전부 OPEN)
entry_time 0건 / entry_config 0건 / entry_context 0건 / progression 0건
scheduler 로그: "on_exit 실패: no attribute 'unrealized_pnl_pct'"  ← 5분마다 27건 반복
```

`on_entry` / `on_exit` / `snapshot` **셋 다** AttributeError로 죽고, 넓은 `except`가 warning 한 줄로 삼켰습니다.

> **이게 안 고쳐졌으면 v137/v138의 `entry_context` 등급 저장도 배포 즉시 무용지물이었습니다.**
> `record.entry_context = market_context` 는 죽는 줄(`first_entry_at`) **뒤**에 있었기 때문입니다.

### 버그 ② 워커가 실패를 성공으로 보고 (전형적 silent bug)

```
[learning_sync] 완료: entered=0 snapped=0 closed=27    ← 27건 종료 처리 "완료"
[TradeLearning] on_exit 실패: ...                       ← 실제로는 27건 전부 실패
```
성공/실패 구분 없이 `closed += 1` 을 세고 있었습니다. 로그만 보면 정상입니다.

### 버그 ③ 예측 학습 데이터 오염 (60%)

`prediction_outcome_worker`가 1h/4h/24h 칸을 **전부 「지금 현재가」**로 채웠습니다.
워커는 1시간마다 도는데, 어떤 예측을 처음 봤을 때 이미 4시간이 지났으면 `outcome_change_1h`에 4시간치가 들어갑니다.

| 저장값 `1h == 4h` (같은 pass에 채워짐) | **397건 / 662건 (60%)** |

> v135 「예측 학습 사이클」이 이 오염된 값으로 심볼 성공률 → confidence를 조정해 왔습니다.

1. **추천 데이터는 2일치(8/12~13)뿐** — 단일 시장 국면입니다. 실매매는 5.5주라 그나마 낫습니다.

3. **소급 재현의 한계** — 진입 시각은 `orders` 첫 ENTRY 체결 기준입니다. 슬리피지·수수료는 반영하지 않았습니다.
4. **필터 시뮬레이션은 「그 거래를 안 했다면」 가정**입니다. 실제로는 자본이 남아 다른 거래를 했을 수 있습니다.
5. **표본 부족 구간**: EMA/VCP A·B등급 실매매(각 0~1건), SAR A등급(9건) — 판정 불가입니다.
