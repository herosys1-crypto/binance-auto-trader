# 🚨 말하기 전에 **재라** — 하루에 오진 3건

2026-08-30 볼밴 3차 0건을 쫓으며 내가 자신 있게 말한 진단이 **연속 3번 반증**됐다.
전부 「코드를 읽고 추론」해서 나온 것이고, 전부 **한 줄 쿼리로 즉시 갈렸다**.

| 내 주장 | 실측 | 갈린 방법 |
|---|---|---|
| 「−5% 강제손절이 볼밴을 자른다」 | 볼밴은 전부 `force_sl_roi_override=10.00`, −10% 에서 잘림 | `event_payload.threshold` 1줄 |
| 「Fix 203 이 프로세스에 안 올라갔다」 | 코드 12:58 / 스케줄러 시작 14:10 = 살아 있음 | `docker inspect StartedAt` vs `ls -l` |
| 「템플릿이 OBV_REVERSE 라 가격 경로를 안 탄다」 | 17건 전부 `PRICE_DOWN_PCT` | 템플릿 1컬럼 |

2026-08-28 에도 같은 일이 있었다(그림자 키 가설 → 그 행은 존재한 적이 없었고
내 fix 가 오히려 그걸 만들었다). 사장님 반응: **"짜증나 몇번을 하는거야"**.

**Why:** 실자금이 걸린 시스템에서 틀린 진단은 시간만 쓰는 게 아니다 —
사장님이 그걸 믿고 설정을 바꾸거나 포지션을 정리하면 **돈이 나간다**.
그리고 매번 틀리면 맞는 말도 못 믿게 된다.

## How to apply

- **가설이 떠오르면 먼저 「이걸 가르는 한 줄은 뭔가」를 쓴다.** 그 한 줄이 없으면
  가설을 말하지 않는다. 대부분 `event_payload` / 컬럼 1개 / 프로세스 시작 시각이면 갈린다.
- **여러 후보를 한 번에 재는 명령 하나**를 만든다. 후보를 하나씩 말하고 하나씩
  틀리는 게 제일 나쁘다 (사장님이 매번 붙여넣어야 한다).
- 말할 때는 **「확정」과 「후보」를 분리해서** 쓴다. 확정만 표로, 후보는 「이걸 재면 갈린다」로.
- 틀렸으면 **한 문장으로 정정하고 바로 다음 측정으로 간다.** 길게 사과하지 않는다.
- `docker compose exec ... grep` 은 **디스크**를 읽는다 — 돌고 있는 파이썬 프로세스의
  코드가 아니다. 배포 여부는 **프로세스 시작 시각 vs 파일 수정 시각**으로만 판정한다.
