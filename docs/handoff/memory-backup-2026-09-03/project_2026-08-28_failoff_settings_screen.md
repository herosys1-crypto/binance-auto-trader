# 🚨 2026-08-28 「모름」이 「꺼짐」으로 표시되던 fail-OFF (Fix 188~193)

사장님: "최대 포지션 30개에서 10개로 자동으로 변경되었어 / 볼밴분할 전략도 켬으로 했는데 껌으로 변해 있었어"

## 🚨 내가 틀린 것 3건 (전부 실측/조사가 반증)

1. **「그림자 키가 화면을 덮고 있다」** → `sajangnim_max_concurrent_positions` **행 자체가 없었다.**
   더 나쁜 건, 그걸 고친다며 넣은 **Fix 188 이 저장할 때마다 그 행을 새로 만들고 있었다**
   = 원래 없던 1순위 키를 내 손으로 설치 = **막으려던 함정을 스스로 팜** → Fix 191 로 철회.
2. **「볼밴 저장이 반영되지 않았다」** → **입증되지 않은 주장.**
   SQLAlchemy 는 **같은 값 대입에 UPDATE 를 내지 않는다** → 사장님이 「켬」을 눌러
   정상 저장됐어도 `updated_at` 은 그대로다. 타임스탬프로 저장 여부를 판정할 수 없다.
3. **「화면 5 ≠ 기본 3 이니 로드 성공」** → 5 를 만드는 코드가 **전 이력에 0건**
   (`git log -S` 확인). 사장님이 타이핑한 **미저장 입력**이었다. 내 추론 근거가 틀렸다.

## ✅ 진짜 원인 = fail-OFF (Fix 192)

**DB 는 처음부터 끝까지 `pump_split_enabled='1'`. 거짓말한 건 화면이다.**
세 겹이 **전부 같은 방향으로** 침묵했다:

1. `_current_bbsplit` 초기값이 `0`(끔) + 예외 통째 삼킴 → **HTTP 200 으로 「끔」**
2. JS `if (r.bbsplit_enabled != null)` → 서버가 그 키를 모르면 **조용히 건너뜀**
3. `<select>` 첫 옵션이 `<option value="0">끔` → **로드 전 화면이 이미 거짓말**

= 「모름」을 표현할 수단이 UI 에도 API 에도 없어서 **「모름」이 「꺼짐」으로 표시**됐다.
돈을 쓰는 전략의 ON/OFF 에서 이 방향의 침묵이 가장 위험하다.

해법: 모르면 `None`(0 은 정말 꺼졌을 때만) / 결손이면 **throw** → 빨간 경고 + 저장 차단 /
첫 옵션 「⏳ 불러오는 중…」(빈 값·disabled) / `api_features` 표식으로
**「git pull 했는데 재시작 안 함」을 화면이 스스로 진단.**

## 30 → 10 은 「자동」이 아니었다

`sajangnim_top_short_daily_limit` 을 쓰는 코드는 **그 PUT 하나뿐** (워커 5곳은 전부 읽기 전용,
alembic·스크립트·raw SQL 에 없음). 자동 기록 경로 **0개** = HTTP PUT 한 건이 온 것.
`onupdate=func.now()` 라 22:56:36 은 **실제 변경 시각**이고 직전 값 ≠ 10.
clamp 산물도 아니다(0~200 안). **하지만 직전 값도 발신자도 확정 불가** — 이력 테이블이 없고
`user_id` 를 Depends 로 받아놓고 `updated_by` 를 안 채웠다 → **Fix 193 으로 감사 기록 추가.**

⚠️ **⚙세팅 카드는 저장 시 항상 전 필드를 보낸다** → 볼밴만 만지려던 저장이 상한까지 덮어쓴다.
사장님이 「자동으로 바뀐 것처럼」 느낀 유력한 이유. (미해결 — 부분 저장 필요)

## Fix 190 = `?v=` 자동화

index.html 의 손으로 적는 캐시 무효화 문자열이 **18개 파일에서 낡아 있었다**
(이번 세션에 고친 UI 파일 전부 포함). `no-cache` 헤더가 실피해는 막고 있었지만
**손으로 올리는 규칙은 반드시 잊힌다 — 전부 잊혔다.**
→ `/admin-ui` 응답에서 **파일 내용 sha1** 로 자동 교체 (`main.py _rewrite_asset_versions`).
경로 탈출/없는 파일은 미적용, 실패 시 fail-open. index.html 에 「손대지 말 것」 주석.
