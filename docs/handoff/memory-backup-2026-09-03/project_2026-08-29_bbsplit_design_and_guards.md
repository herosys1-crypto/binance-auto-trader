**Fix 203** — 볼밴 2·3차는 **지표 게이트 제외**. Fix55/114 는 「하락이 멈춘 뒤 사라」인데
볼밴은 **하락 중에 나눠 사는** 전략이라 정면 충돌. 실측 3차 체결 **0건**의 진짜 원인.
Fix 195 로 트리거를 고쳤는데도 0건이었고 사유는 전부 "Fix114 정점 미확인".
→ 「작게 넣고(100) 얕게 잘리는(−7.85%)」 최악 조합이었다. 3차까지면 손절선 −10.41%.
   손실 10건의 최저 도달 깊이 역산 = **최소 6건은 3차 구조였다면 손절당하지 않았다.**
⚠️ 다른 전략은 게이트 그대로 (#1488 −6,981 이후 만든 안전망).

**Fix 205** — TP1 15% → **5%** (원문 복원). 🚨 `strategy_service` 가 **모든 전략에
`tp1_pct_override = 15`** 를 박으므로 템플릿만 바꾸면 무효 → 인스턴스에도 5 를 명시.

**Fix 206** — 트리거·손절도 설정화(`pump_split_steps` / `pump_split_sl_roi`).
🚨 세 값(자본·트리거·손절)은 **얽혀 있다** — 손절만 −5% 로 낮추면 3차가 죽는다.
각 sanitizer 는 형식만 보고, **저장 직전에 조합으로** 검산 후 실패 시 롤백.
미리보기가 평단·손절선·TP1 을 즉시 계산하고 죽는 조합이면 ⛔ 경고.

## 🚨 Fix 208 — 학습 표본이 없던 근본 원인 = 스키마 불일치

```
생산자 long_bottom_detector  {"15m": {"rsi_now", "cci_now"}}
생산자 macd_reversal_15m     {"rsi_15m", "cci_15m", "obv_slope_15m"}
생산자 mtf_snapshot.capture  {"tf": {"15m": {"rsi", "cci"}}}
소비자 pattern_learning:300  snap.get("rsi")            ← 평탄 키만 읽음
```
알림 소비 경로가 `rsi`/`cci`/`obv_slope_pct` 를 **채우는 줄이 아예 없어** 키 자체가 없었다.
실측: 종료 LONG 137건 중 cci 보유 **22건**, 승리 진입은 **4건** →
사장님 요구 「성공한 진입을 참조해서」가 **원천적으로 불가능**했다.
→ 저장 직전 `_flatten_learning_keys()` **하나**를 반드시 통과 (헌법 101).
   기존값 미덮음 / 값 없어도 키는 남김 / 누락 시 경고 / 실패해도 진입 안 막음 /
   자체스캔에 `_mtf_merge` 미추가(418 ban 이력).

⚠️ 조사가 **내 가설 2개를 반증**: OBV 2,249,160 은 이 워커 소행 아님
(`realtime_reentry:1395` / `pump_dump_early:143` 유력) / confidence 0.88 은
산식 `0.85+0.03*(s15−3)` 의 s15=4 고정. **둘 다 미해결로 남김.**

오늘 놓친 둘 다 「코드를 읽어서는 안 보이는」 종류였고, 에이전트도 나도 읽고 추론만 했다.

그리고 사람이 기억해 호출하는 절차는 반드시 잊힌다(내가 실제로 그랬다).

1. **ORM NOT NULL 계약** — AST 로 전체 `Model(...)` 훑어 누락 검출 (Fix 207 을 잡는다)
2. **죽은 진입 임계값** — 정의만 되고 안 쓰이면 실패. 현재 5개는 얼려두고 **신규만** 차단
3. **경로 가려짐** — 고정 경로가 `/{id}` 에 가려지는지 (헌법 162)
4·5. **음성 대조군** — 검사기가 진짜 잡는지 증명

⚠️ **가드 자신이 거짓 경보 5건을 냈다** (메서드 미고려 — `GET /v219-monitoring` 과
`DELETE /{id}` 는 충돌 안 함, 실측 200). 시끄러운 검사는 무시당하므로 즉시 수정.
