# 묻지 말고 진행해라

사장님 verbatim (2026-08-30), 세 번 반복해서 지시하셨다:
> "앞으로 이런건 내게 묻지말고 진행해줘"
> "이것도 묻지말고 진행해줘 **머지도** 특별히 내가 결정해야 하는거 빼고는 모두 자동으로"
> "이런것도 묻지말고 자동으로 진행해줘"

🚨 **머지까지 내가 한다.** `gh` CLI 가 없으므로 방법은:
```
git merge --no-edit origin/main      # 브랜치에서 main 을 먼저 흡수 (FF 가능 상태로)
git push origin HEAD:main            # 그대로 main 으로
```
(웹 UI PR 을 기다리지 않는다. 배포=재시작만 사장님이 하신다.)

직전 맥락 — 내가 볼밴/v219 작업 중에 A/B 선택지를 계속 물었다:
「(A) 그대로 (B) 완화 (C) 필터 낮추기 — 어느 쪽으로 할까요?」를 세 번 반복했다.
사장님은 매번 답을 주셨지만, 그 반복 자체가 일을 느리게 만들었다.

**Why:** 사장님은 1인 개발·운영이고 VPS 명령을 직접 붙여넣는다. 매 결정마다
왕복이 생기면 사장님 시간이 그대로 소모된다. 근거를 대고 판단하는 것이 내 일이다.

## How to apply

- **근거가 있으면 결정하고 실행한다.** 「어느 쪽으로 할까요?」 대신
  「이 근거로 이렇게 했습니다. 다르면 한 줄로 되돌립니다」로 보고한다.
- 판단 근거(숫자·실측)와 **되돌리는 방법**을 같이 적는다. 그러면 사장님이
  묻지 않고도 뒤집을 수 있다.
- 위험한 선택은 **막는 쪽(보수적)으로** 먼저 넣고, 실측 로그를 붙여
  하루 뒤 데이터로 조정한다. 감으로 완화하지 않는다.
- 여전히 **묻는 것**: 자금이 실제로 나가는 조작(주문/취소/청산), 파괴적 작업
  (DB 삭제·롤백), 그리고 사장님 사상 자체가 바뀌는 변경.
  → [[feedback_workflow]] 의 「파괴적 작업만 명시 승인」과 같은 선.
- 코드 변경은 내가 결정해서 넣고, **배포(재시작)는 사장님이 하신다** — 그건 유지.
