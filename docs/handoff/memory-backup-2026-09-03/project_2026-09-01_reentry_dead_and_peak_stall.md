# 🚨 2026-09-01 — 「일일」이 일일이 아니었다 + 정점-주춤 신설

## ① 최대 발견 — 재진입이 9일간 0건 (Fix 262)

`_auto_bb_reset_at()` 은 `auto_bb_break_reset_at` 행이 있으면 **그 값을 그대로**
돌려줬다. 그 행에 `2026-08-23 07:34` 가 들어 있었고 사장님이 그 뒤 리셋을 안
누르셨으므로 **「오늘」의 기준이 8.7일 전에 멈춰** 있었다.

```
_count_reentry_used_today() = 20 / 한도 20   -> remaining 0 (영구)
RT_REENTRY suggestion 전 기간 = 딱 20건       <- 그게 전부 「오늘 것」
실제 재진입 전략 (5일)        = 0건
_count_used_slots()          = 591 / 하루 20
```

🚨 **로그는 「재진입 일일 한도 소진: 20/20」이라고 정확히 말하고 있었다.**
그 숫자가 누적이라는 것만 아무도 몰랐다. 「한도 소진」 메시지를 보면
**분자가 진짜 오늘 것인지 반드시 확인할 것.**

수정 = `max(stored, KST자정)`. 파급 4곳(`realtime_reentry` / `auto_bb_breakdown` /
`auto_short_at_top` / UI)이 한 함수를 공유하므로 한 줄로 다 고쳐졌다.
고친 뒤 `_count_used_slots` 591→21 (여전히 20 초과 = 신규 진입 무변화),
`_count_reentry_used_today` 20→0 (재진입만 해제). **배포 후 확인**:
`scanned=0` → **`scanned=30 candidates=30`**, 사유가 `rebound_too_small=14 /
already_active=9 / indicator_gate_need2=7` = 정당한 조건 미달로 바뀜.

Fix 263 = 재진입 **전용 동시 슬롯 10** (`sajangnim_reentry_concurrent_slots`).
옛 코드는 전체 상한(50)이 차면 재진입을 통째로 return 했다 — 신규 진입이 슬롯을
다 먹으면 재진입은 차례가 오지 않는다. 일일 한도도 20→**10** (사장님 지시).

## ② 정점-주춤 단계 진입 (Fix 260) — 사장님 신 지시

> "2단계부터는 차트와 보조지표가 조정으로 바뀌면**이 아니라 최고점에서** 들어가야 …
>  최고점으로 가다가 **주춤**할때 2단계, **다시 최고점**으로 가면 대기해서 **꺾이면** 3단계"

- **「최고점」 = 불리 방향 극값**. SHORT=신고점 / **LONG=신저점**.
  LONG 을 가격 최고점으로 잡으면 가격 트리거와 방향이 반대라 진입 불가.
  (실측: SHORT 단계2 트리거 = 진입가 **+2.06% 위** / LONG = **−1.95% 아래**, 간격 2%p)
- 🚨 **조건을 더하면 수학적으로 불가능하다.** `should_fire = mark >= trigger` 라
  되돌아오면 mark 가 trigger 아래로 내려가 그 자리에서 죽는다.
  → 조건을 더하지 말고 **비교 주체를 mark → 러닝 극값**으로 바꿀 것.
- **「가다가」(=극값이 trigger 까지 전진)가 지배 변수.** 이걸 빼면 −20.94,
  넣으면 **+97.4 USDT**. 주춤은 4~5봉 최적, 6봉부터 급락. 과적합 검사 통과
  (양쪽 절반 +23.30 / +55.13).
- 기존 Fix 218 게이트(`peak_confirmation`)는 RSI≤35/CCI≤−80 을 요구하는데
  볼밴 분할이 다루는 24h 변동 15%+ 급등 종목엔 **구조적으로 거짓** → 단계3 7일 0건.

🚨 **`stage_no IS NULL` 인 ENTRY 주문 = `add_position_now` 경로**다. 자본 폭증을 추적할 때
   이 쿼리 하나면 된다. `total_capital` 이 템플릿 `stage1_capital` 보다 크면 전부 이 경로.

Fix 213 이 볼밴 분할에서 같은 사고를 잡았지만(피라미딩 **대상에서 제외**) 나머지 경로는
그대로였다 — **제외는 한 전략만 구하고 나머지를 놔둔다.** Fix 269 는 `add_position_now`

「손절 시 잃는 USDT」를 추가 전과 같게 유지한다 (`새 ROI = 이전손실 / 새자본 x 100`).
