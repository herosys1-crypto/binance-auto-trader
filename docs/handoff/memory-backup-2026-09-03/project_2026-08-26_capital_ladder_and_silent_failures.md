# 자본 사다리 10/300/600 + 조용한 실패 대청소 (2026-08-26)

## 🎯 사장님 최종 지시 (verbatim)

> "10 300 600으로 마틴게일 설정"
> "10 진입 → -5% → 조건 충족 대기 → 300 진입 ... 손실이 -5%면 청산하고 다음단계 600 모니터링"
> "복잡하면 10 -5%일때 청산하고 다음단계 모니터링 대기해도 됩니다."  ← **채택 (청산 후 대체)**
> "수익일떄 10 +5% 마틴게일 300 진입 ... 300한번더 ... 이렇게 두번만 ... +15% 익절시작"
> "손실일때 -10%정도되면 청산하고 마틴게일 1단계 모니터링 대기"

## ✅ 확정 동작 (실측 검증 완료)

```
사다리: ['10','300','600'] | max_stage: 3
1/2/3단계: 10.00 300.00 600.00 | 피라미딩 1회: 300
```

- **손실**: 1단계 10 → −5% 청산(−0.5) → 조건 충족 → 300 → −5% 청산 → 600 → 소진 시 **1단계로 리셋**
- **수익**: ROI +5% → 300 추가 → 지속 시 한번 더 (**최대 2회**)
- **물타기 아님** — 각 단계는 청산 후 대체. 사장님이 단순안을 허용했고,
  승률 3.7% 상황에서 물타기는 「틀린 방향에 자본 추가」라 위험해서 이 쪽을 택함.
  매 단계 독립 진입이라 「조건에 맞으면」이 단계마다 재판정된다.

**설정 키**: `sajangnim_capital_ladder="10,300,600"` / `sajangnim_max_stage=3`
⚠️ `get_max_stage` 는 저장값을 사다리 길이로 **깎기만 하고 끌어올리지 않는다**.
   사다리를 늘리면 max_stage 를 함께 올려야 한다 (UI 저장 시 자동 동기화 = Fix 145).

## 🚨 헌법 신설

**헌법 101: 「설정했는데 안 먹는다」의 원인은 대개 읽는 함수가 여러 개인 것!**
- 값 하나에 읽는 경로가 둘 이상이면 반드시 어긋난다 (Fix 143 = 1단계가 300)
- 새 설정을 넣으면 **그 값을 읽는 모든 함수를 grep 으로 열거**해 전부 바꿀 것

**헌법 102: 서로 모순될 수 있는 설정 2개를 두지 말 것!**
- 사다리(3칸) vs max_stage(2) → 조용히 잘림 (Fix 145)
- 파생 가능한 값은 **파생시키고 UI 는 읽기 전용**으로

**헌법 103: 게이트를 켤 때 「사장님 시나리오가 통과하는지」 먼저 시뮬레이션할 것!**
- OBV 게이트를 그대로 켰다면 「급락 후 반등 LONG」과 「급등 정점 SHORT」를 **둘 다** 차단했다
- Fix 114(24h 절대 필터)와 **같은 실수를 두 번** 했다 = 방향만으로 차단 금지, 극단만 차단

**헌법 105: 게이트를 고칠 땐 「사유를 숫자로」 먼저 세분화할 것!**
- LONG 추적에서 `not_detected=40` → `nd:B=39` → `nd:B1=16 B3=13 B2=7 B0=3` 3단계 세분화
- 내 사전 가설(B0)은 **틀렸다**. 실제는 B1/B3. 숫자 없이 고쳤으면 헛짚었다
- 층이 여러 겹일 때 「추측으로 한 겹 열고 다음을 또 추측」하면 시간과 자본을 낭비한다

**헌법 106: 서로 모순되는 AND 게이트를 만들지 말 것!**
- 게이트2「MACD 반등 시작」 ↔ 게이트3「RSI≤40 깊은 과매도」 = 실측 13/13 전멸
- MACD 가 turn 했으면 RSI 는 이미 회복돼 있다 = 두 조건이 동시 성립할 창이 거의 없다
- 새 조건 추가 시 「기존 조건과 동시에 성립 가능한가」를 수치로 확인할 것

**헌법 107: 「포지션 추가」와 「전략 생성」을 혼동하지 말 것!**
- Binance 는 한 종목/방향에 **통합 포지션 하나**뿐이다
- 추가 = `add_position_now` (평단/qty 갱신) / 신규 = `_create_auto_bb_strategy`
- 추가를 신규로 구현하면 중복 가드에 막히고, 뚫으면 익절/손절이 충돌한다
- 추가는 동시보유 상한을 소비하지 않아야 한다 (새 포지션이 아니므로)

**헌법 108: `ACTIVE_LIKE` 조회에는 반드시 `is_archived=False` 를 붙일 것!**
- 활성 상태 + 아카이브됨 = 모순인데 14곳 중 11곳이 필터 없음 (Fix 158)
- 자본 투입 경로면 「종료된 전략에 돈을 넣는」 사고가 되고,
  `active_syms` 용도면 「종료된 심볼에 재진입 불가」로 진입이 조용히 막힌다

**헌법 109: 진단 도구가 거짓말하면 없느니만 못하다!**
- 코드 삽입을 「줄 번호」로 하지 말 것 — 이후 수정으로 줄이 밀려 라벨이 어긋난다 (Fix 160)
- 실제: `no_avg_or_mark` 라벨이 `roi_pct < 5%` 조건에 붙어 있었다
  → 나는 이를 「평단/마크 결손 = SL 위험」으로 오독해 사장님께 **잘못된 경보**를 냈다
- 사유 라벨을 넣은 뒤 「라벨 ↔ 실제 조건」을 기계적으로 대조 검증할 것
- 같은 작업을 조건 문자열 기준으로 한 LONG 워커(Fix 149/151)는 전부 정확했다

**헌법 110: select 는 「옵션에 없는 값」을 표시하지 못한다!**
- 사장님 실측: 운영 상태 `28/40` 인데 세팅 화면은 `20` (옵션이 …15/20/30 뿐)
- 그 상태로 저장을 누르면 20 이 전송돼 **설정이 조용히 되돌아간다** (Fix 161)
- 서버가 자유 범위(0~200)를 받는 값은 UI 도 자유 입력(number)이어야 한다
- 헌법 85(화면 = 실제)의 구체적 재발 형태

**헌법 104: 조기 return 은 워커가 아니라 「공통 래퍼」부터 볼 것!**
- 개별 워커를 4번 고치고 나서야 `guarded_job` 이 공통 상류임을 발견 (Fix 139)
