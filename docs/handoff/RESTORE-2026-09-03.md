## 1. 메모리 복원 (가장 중요)

메모리에는 **사장님 매매 사상, 과거 사고의 원인, 반증된 가설**이 들어 있다.
저장소 코드보다 이쪽이 더 값질 수 있다 — 코드는 다시 읽으면 되지만, "재봤더니 반대였다"는
다시 재기 전에는 알 수 없다.

### 🚨 함정: 메모리 폴더 이름은 **프로젝트 경로에서 자동 생성**된다

옛 PC 경로가 `C:\Users\user\바이낸스\binance-auto-trader` 였기 때문에
폴더 이름이 `C--Users-user------binance-auto-trader` 가 되었다
(한글 「바이낸스」가 하이픈으로 바뀌면서 `------` 가 됐다).

**새 PC에서 저장소를 다른 경로에 두면 폴더 이름이 달라져 옛 메모리를 못 읽는다.**

→ 두 가지 방법 중 하나를 택한다.

**방법 A (권장) — 옛 PC와 같은 경로를 쓴다**

새 PC에서도 `C:\Users\user\바이낸스\binance-auto-trader` 에 clone 한다.
그러면 폴더 이름이 저절로 같아진다.

```bash
mkdir -p "/c/Users/user/바이낸스" && cd "/c/Users/user/바이낸스" && git clone https://github.com/herosys1-crypto/binance-auto-trader.git
```

그 다음 메모리를 제자리로 복사한다.

```bash
mkdir -p "/c/Users/$USER/.claude/projects/C--Users-user------binance-auto-trader/memory" && cp -r "/c/Users/user/바이낸스/binance-auto-trader/docs/handoff/memory-backup-2026-09-03/." "/c/Users/$USER/.claude/projects/C--Users-user------binance-auto-trader/memory/"
```

복원 확인 (83개가 나와야 한다):

```bash
ls "/c/Users/$USER/.claude/projects/C--Users-user------binance-auto-trader/memory" | wc -l
```

**방법 B — 다른 경로를 쓸 때**

새 경로로 Claude Code 를 한 번 실행해 폴더가 자동 생성되게 한 뒤,
`~/.claude/projects/` 아래에 **새로 생긴 폴더 이름**을 확인하고 그 안의 `memory/` 로 복사한다.

```bash
ls "/c/Users/$USER/.claude/projects/"
```

> ⚠️ 폴더 이름을 손으로 지어내지 마라. Claude Code 가 만든 이름을 확인해서 쓴다.

복원 후 `MEMORY.md` 가 읽히는지 확인한다 — 세션 시작 시 이 파일이 컨텍스트에 올라온다.

## 2. 미커밋 작업 복원

옛 PC의 3개 worktree 에 **커밋되지 않은 작업**이 있었다. 그대로 두면 새 PC에서 사라진다.

| worktree | 브랜치 | 무엇이 있었나 |
|---|---|---|
| `main` | `main` | 문서 2건 (untracked) |
| `charming-albattani-3f588f` | `feat/external-positions` | **미push 커밋 1개** + 문서 1건 |
| `loving-rhodes-52788c` | `feat/c-full-archive-filter-restore` | 소스 수정 2파일 + **새 워커 2개 (39KB)** |

각 폴더 구성:

- `uncommitted.patch` — tracked 파일의 수정분 (`git apply` 로 되돌린다)
- `staged.patch` — staged 된 수정분 (있으면)
- `untracked/` — 추적되지 않던 새 파일들 (그대로 복사하면 된다)
- `unpushed/` — 원격에 없는 커밋들 (`git am` 으로 되돌린다)
- `unpushed-commits.txt` / `untracked-list.txt` — 목록

### 2-1. 가장 값진 것부터: `loving-rhodes` 의 새 워커 2개

`long_bottom_detector_worker.py` (27KB) 와 `auto_long_at_bottom_worker.py` (12KB) 는
**원격 어디에도 없는 작업**이다.

먼저 **현재 main 에 같은 이름의 파일이 있는지** 확인한다. 있다면 덮어쓰지 말고 내용을 비교하라.

```bash
ls -la backend/app/workers/long_bottom_detector_worker.py backend/app/workers/auto_long_at_bottom_worker.py
```

`diff` 로 차이를 먼저 본다:

```bash
diff backend/app/workers/auto_long_at_bottom_worker.py docs/handoff/wip-backup-2026-09-03/loving-rhodes_feat-c-full-archive-filter-restore/untracked/backend/app/workers/auto_long_at_bottom_worker.py
```

> 🚨 **바로 복사하지 마라.** main 쪽이 더 최신일 수 있다.
> 위 diff 를 읽고 어느 쪽을 살릴지 판단한 뒤에 옮긴다. 판단이 서지 않으면 그대로 두고
> 백업 폴더에서 참고만 하라 — 잃어버리지만 않으면 된다.

### 2-2. tracked 수정분 되돌리기

브랜치를 먼저 만들고 그 위에 얹는다. **main 에 바로 적용하지 마라.**

```bash
git checkout -b restore/loving-rhodes-wip origin/main
```

패치가 깨끗이 붙는지 먼저 검사한다 (`--check` 는 실제로 적용하지 않는다):

```bash
git apply --check docs/handoff/wip-backup-2026-09-03/loving-rhodes_feat-c-full-archive-filter-restore/uncommitted.patch
```

문제가 없으면 적용한다:

```bash
git apply docs/handoff/wip-backup-2026-09-03/loving-rhodes_feat-c-full-archive-filter-restore/uncommitted.patch
```

> ⚠️ `--check` 가 실패하면 그 파일이 그 사이 바뀐 것이다. `git apply --3way` 로 3방향 병합을
> 시도하거나, 패치를 열어 손으로 옮겨라. 억지로 `--force` 하지 마라.

### 2-3. 미push 커밋 되돌리기 (`charming-albattani`)

커밋 1개: `feat(positions): 외부 포지션 가시성 — 도구 밖 수동 진입 표시 (사장님 요구)`

```bash
git checkout -b restore/external-positions origin/main
```

```bash
git am docs/handoff/wip-backup-2026-09-03/charming-albattani_feat-external-positions/unpushed/*.patch
```

> ⚠️ `git am` 이 충돌하면 `git am --abort` 로 되돌린 뒤, 패치 파일을 열어 손으로 반영하라.

### 2-4. 문서들

`untracked/` 아래 문서는 그냥 복사하면 된다.

```bash
cp -r docs/handoff/wip-backup-2026-09-03/main/untracked/. .
```

## 3. 이 백업이 **담고 있지 않은 것**

아래는 저장소에 넣을 수 없다(비밀). **옛 PC에서 직접 옮겨야 한다.**

| 항목 | 원래 위치 | 옮기는 법 |
|---|---|---|
| SSH 개인키 (VPS 접속) | `~/.ssh/id_ed25519` + `.pub` | USB 등 **오프라인 매체**로 직접 복사. 채팅·이메일로 보내지 마라. 또는 새 PC에서 새 키를 만들어 VPS 의 `authorized_keys` 에 **추가**한다(옛 키는 지우지 말 것 — 새 키가 안 되면 못 들어간다) |
| `backend/.env` | 저장소 안 (gitignore 됨) | VPS 에 이미 있는 파일이 정답본이다. 로컬 개발용은 `backend/.env.example` 를 복사해 사장님이 직접 채운다 |
| 암호화 키 (`ENCRYPTION_KEY`) | `.env` | 🚨 **이걸 잃으면 DB 의 `api_key_enc` 를 복호화할 수 없다.** 거래소 키를 다시 발급해 재등록해야 한다. VPS 의 `.env` 에 있으니 VPS 접속이 되면 살아 있다 |
| 바이낸스 API 키 | 바이낸스 계정 | 🚨 Claude 는 API 키를 만들거나 입력하지 않는다. **사장님이 직접** 발급·입력한다 |

> 🚨 **순서 주의**: SSH 키를 먼저 확보하라. VPS 에 못 들어가면 `.env` 도 암호화 키도 볼 수 없다.
> 옛 PC를 지우기 전에 **새 PC에서 VPS 접속이 되는 것을 반드시 확인**하라.
