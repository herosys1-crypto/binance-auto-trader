## 🎯 사장님 사상

### 왜 이 spec인가
사장님이 유튜브 매매법을 정리해서 「학습한 자료와 같이 활용할 수 있게」 요청.

**핵심 = 남의 매매법을 그냥 믿지 않는다.**
- 남이 좋다는 셋업 → 우리 시스템이 **진입 시점에 등급으로 기록**
- 거래가 끝나면 → **실제 손익과 대조**
- = 「이 매매법이 진짜 우리 계좌에서 돈이 되는가?」를 **숫자로** 확인!

### 왜 자동 주문을 안 붙였나 (중요!)
- 메인넷 = **실자금** (헌법 1번)
- 검증 없는 코드 금지 (헌법 4번)
- 이 로직은 **아직 우리 데이터로 검증된 적 없음** = 지금 자동 진입 붙이면 검증 없는 실탄 발사!
- → **1단계: 분석 + 학습 저장만** → 표본 쌓임 → 등급별 승률 확인 → **그 다음에** 자동화 판단!

## 📊 원본 로직 (영상 5단계)

| 단계 | 내용 |
|------|------|
| 1. 지표 | 단순(SMA) 아닌 **지수(EMA) 10 / 20 / 50** + 거래량 |
| 2. 1차 필터 | 하락 후 **첫 반등은 무조건 관망** (가짜 반등 회피!) |
| 3. 2차 셋업 | **정배열**(10>20>50) + **변동성 수축(VCP)** + **거래량 감소** |
| 4. 진입 | 횡보 구간 **전고점 돌파** + **거래량 폭발** |
| 5. 청산 | 손절 = 돌파 지지선/박스 하단 이탈 / 익절 = **20 EMA 몸통 이탈 종가** |

### 원본 MTF 배분
> **4시간봉에서 큰 물길을 찾고, 1시간봉에서 덫을 놓은 뒤, 15분봉에서 방아쇠를 당긴다.**

| 봉 | 역할 | 원본 기준 |
|----|------|----------|
| **4H** | 나침반 | 50 EMA 우상향 + 가격이 그 위 → 아니면 매수 금지 |
| **1H** | 작전 지도 | VCP 형성, 거래량 마름, 전고점에 수평선 |
| **15m** | 방아쇠 | 1H 저항선 돌파 순간 진입 / 직전 스윙 로우 손절 / 15m 20EMA 이탈 시 절반 익절 |

## 🔄 우리 시스템 변환 (원본과 다른 점)

원본은 **주식 매수 전용**. 우리는 **선물 LONG/SHORT 양방향** = 전 규칙을 대칭 확장했습니다 (헌법 5번 대칭성).

| 항목 | LONG (원본) | SHORT (대칭 확장!) |
|------|-------------|--------------------|
| 4H 추세 | 가격 > EMA50 AND EMA50 우상향 | 가격 < EMA50 AND EMA50 **우하향** |
| 1H 배열 | 정배열 10 > 20 > 50 | **역배열** 10 < 20 < 50 |
| VCP 수축 | 변동폭 축소 | **동일** (변동성 수축은 방향 무관!) |
| 거래량 고갈 | 매도세 소진 | **동일** (매수세 소진!) |
| 1차 필터 | 첫 **반등** 무시 | 첫 **반락** 무시 |
| 돌파선 | 최근 20봉 **고점** | 최근 20봉 **저점** |
| 돌파 | 고점 **상향** 돌파 | 저점 **하향** 돌파 |
| 손절 | 직전 스윙 **로우** | 직전 스윙 **하이** |
| 익절 | 20EMA **아래로** 종가 이탈 | 20EMA **위로** 종가 이탈 |

## 🎛 기계화된 판정 규칙 (실제 코드 파라미터)

`backend/app/services/ema_vcp_analyzer.py` — 모든 임계값은 클래스 상수 = 한 곳에서 수정 (헌법 6번 단일 진실).

### 1) 4H = 나침반

```
EMA50 기울기 = (EMA50[-1] - EMA50[-6]) / EMA50[-6] × 100
  기울기 > +0.1% AND 가격 > EMA50  → UP   (LONG 허가!)
  기울기 < -0.1% AND 가격 < EMA50  → DOWN (SHORT 허가!)
  그 외                              → FLAT (양방향 금지 = 관망!)
```
| 상수 | 값 | 의미 |
|------|-----|------|
| `SLOPE_LOOKBACK` | 5 | 기울기 = 5봉 전 대비 |
| `SLOPE_FLAT_PCT` | 0.1 | ±0.1% 미만 = 횡보 취급 |

### 2) 1H = 작전 지도

**⚠️ 진행 중 봉 제외!** VCP / 거래량 / 돌파선은 **완료봉만** 사용 (진행 중 봉 = 데이터 불완전 = silent bug 원인!).

```
① 배열     : EMA10/20/50 순서 (LONG 정배열 / SHORT 역배열)
② VCP 수축 : 최근 18 완료봉을 6봉씩 3구간
             각 구간 변동폭% = (구간 최고가 - 구간 최저가) / 구간 평균종가 × 100
             수축 인정 = (구간1 > 구간2 > 구간3) OR (구간3 ≤ 구간1 × 0.66)
③ 거래량   : 최근 6봉 평균 ≤ 이전 12봉 평균 × 0.8  → 고갈!
④ 돌파선   : 최근 20 완료봉 최고 high (LONG) / 최저 low (SHORT)
⑤ 첫반등   : 최근 40봉에서 종가가 EMA20을 상향(LONG)/하향(SHORT) 교차한 횟수
             1회 이하 = 「첫 파동」 = 관망! / 2회 이상 = 바닥 다지기 통과!
```
| 상수 | 값 |
|------|-----|
| `VCP_WINDOW` / `VCP_SEGMENTS` | 18봉 / 3구간 |
| `VCP_CONTRACT_RATIO` | 0.66 |
| `VOL_DRY_RATIO` | 0.8 |
| `PIVOT_LOOKBACK` | 20봉 |
| `RALLY_LOOKBACK` | 40봉 |

**셋업 완성 = ① AND ② AND ③ AND (⑤ 통과)**

> 📌 ⑤ 「첫 반등 무시」는 원본이 **눈으로 보는 판단**입니다. 코드는 **EMA20 교차 횟수**로 근사했습니다. 완벽한 재현이 아니라 **기계화 가능한 대용 지표**임을 명시합니다 (헌법 3번 silent bug 금지 = 근사를 근사라고 적는다).

### 3) 15m = 방아쇠

```
돌파(장중) : 진행 중 봉 high > 돌파선 (LONG) / low < 돌파선 (SHORT)  ← 가장 빠른 포착
돌파(확정) : 직전 완료봉 종가가 돌파선 통과                            ← 신뢰도 높음
거래량 폭발: 직전 완료봉 거래량 / 이전 20봉 평균 ≥ 1.5
             (진행 중 봉은 거래량이 아직 안 찼으므로 = 완료봉 기준!)
손절       : 최근 10 완료봉 스윙 로우(LONG) / 스윙 하이(SHORT)
리스크%    : |현재가 - 손절가| / 현재가 × 100
절반 익절  : 15m EMA20 종가 이탈
전량 익절  : 1H EMA20 종가 이탈
```

## 🏅 셋업 등급 (학습의 핵심 키!)

| 등급 | 조건 | 단계 | 의미 |
|------|------|------|------|
| **A** | 4H 허가 + 1H 셋업 완성 + 15m 돌파(**장중 or 종가**) + 거래량 폭발 | `TRIGGER` | 🎯 지금이 방아쇠! |
| **B** | 4H 허가 + 1H 셋업 완성 (돌파 X) | `SETUP` | ⭐ 덫 설치 완료, 대기! |
| **C** | 4H 허가만 | `WATCH` | 👀 셋업 형성 중 |
| **D** | 4H **역방향** (or 데이터 부족) | `AVOID` / `UNKNOWN` | 🚫 진입 금지! |

**점수 배분 (합계 100)**

| 항목 | 점수 |
|------|------|
| 4H 추세 허가 | 30 |
| 1H 배열 | 20 |
| VCP 수축 | 15 |
| 거래량 고갈 | 10 |
| 첫 반등 필터 통과 | 10 |
| 15m 돌파 (종가 10 / 장중 5) | 10 |
| 15m 거래량 폭발 | 5 |

> **D등급은 다른 조건이 전부 좋아도 D입니다.** 영상의 대원칙 = 「4시간봉 역방향이면 무조건 금지」 (기울기 필터가 최상위!).
>
> A등급은 **장중 돌파**도 인정합니다 (= 영상의 「15분봉으로 가장 빠르게 포착」). 다만 신호 문구에 `⏳ 장중 돌파 중! 종가 확정 대기!`로 구분 표시되니, 확정을 원하면 **종가 돌파(`breakout_closed`)** 를 기다리시면 됩니다.

## 🎓 학습 시스템 연결 (= 사장님 요청의 핵심!)

### 문제였던 점
기존 `trade_learning_records.entry_context` = **항상 빈 `{}`** 였습니다.
`learning_sync_worker`가 `on_entry(s)`를 시장 상황 없이 호출했기 때문 = **진입 당시 차트가 어땠는지 기록이 없음!**

### 신 흐름

```
[진입]  learning_sync_worker (5분마다)
          └ 신규 record 발견
            └ EMAVCPAnalyzer.analyze(symbol, side)
              └ to_learning_context() = 압축 (등급 + 플래그 + 레벨)
                └ entry_context = {"ema_vcp": {...}}        ← 진입 당시 셋업 등급 박제!

[진행]  snapshot (기존 그대로)

[종료]  on_exit → insights (기존 그대로)

[대조]  GET /api/v1/trade-learning/setup-stats
          └ CLOSED 기록의 entry_context.ema_vcp.grade × 실제 pnl_pct
            └ 「A등급 평균 +X% vs D등급 평균 +Y%」                ← 검증 결론!
```

### 저장 형식 (`entry_context.ema_vcp`)

```json
{
  "available": true,
  "grade": "A", "stage": "TRIGGER", "score": 90,
  "trend_4h": "UP", "trend_ok": true,
  "aligned_1h": true, "vcp_contracting": true, "volume_dry": true,
  "first_rally_only": false, "rally_count": 3,
  "breakout_closed": true, "volume_spike": true,
  "levels": {
    "breakout": 130.5, "stop_loss": 99.5, "risk_pct": 2.4,
    "exit_half_15m_ema20": 100.8, "exit_full_1h_ema20": 128.1
  }
}
```
전체 결과가 아닌 **압축본**만 저장 (JSONB 크기 절약 + 집계 키만 유지).

### 데이터 위생 규칙 (⚠️ 중요)

**이미 종료된 전략의 record를 뒤늦게 만들 때는 EMA/VCP를 저장하지 않습니다.**
- 지금 차트는 「진입 당시」가 아님
- 가짜 등급이 승률 통계를 오염 = **분석 silent bug**
- → `no_context` 카운트로만 표시하고 집계에서 제외!

### 집계 API 산출물

```
GET /api/v1/trade-learning/setup-stats?days=90
```
| 필드 | 내용 |
|------|------|
| `grades` | 등급별 count / win_rate / avg_pnl_pct / best / worst |
| `flags` | 조건별 (`trend_ok=Y/N`, `vcp_contracting=Y/N`, `volume_spike=Y/N` …) 승률 → **어떤 조건이 실제로 돈이 됐나?** |
| `graded_total` | 등급 있는 종료 거래 수 |
| `no_context` | 등급 없는 옛 기록 수 (집계 제외!) |
| `verdict` | 사장님용 한 줄 결론 (표본 10건 미만이면 「표본 부족」) |

> **표본 10건 미만 = 판정 금지.** 몇 건으로 「이 매매법 좋다/나쁘다」 결론 내면 그게 제일 위험합니다.

## ⚠️ 한계와 주의 (숨기지 않고 명시)

1. **백테스트 안 했습니다.** 과거 데이터 검증 없이 = 파라미터(0.66 / 0.8 / 1.5 등)는 영상 설명 기반 **초기값**입니다.
2. **「첫 반등 무시」는 근사입니다.** EMA20 교차 횟수 ≠ 사람 눈의 파동 판단.
3. **원본은 주식 스윙**입니다. 선물 레버리지 + 24시간 시장 + 알트코인 변동성에서 그대로 통할 보장 없음 → 그래서 학습 대조를 붙였습니다.
4. **자동 주문 X.** 지금은 사장님 판단 보조 + 데이터 수집 전용입니다.
5. **손절/익절 값은 「기준선」**입니다. 우리 시스템의 실제 SL/TP(강제 SL, 트레일링, TP1 옵션)를 대체하지 않습니다.

## 📚 관련 헌법

- 헌법 1번: 메인넷 = 실자금 → **자동 주문 X**
- 헌법 3번: silent bug 금지 → **fail-safe deny + 근사는 근사라고 표기**
